::message{from="식빵두쪽"}
공개 회원만 검색되게 만들었거든. 그런데 검색어를 이상하게 넣으면 비공개 소개도 나온대. 어떤 입력에서 그런지 같이 봐줄래?
::

**식빵두쪽**이 만든 작은 커뮤니티에는 회원 이름으로 소개를 찾아보는 검색 페이지가 있다.
회원은 공개 여부를 정할 수 있고, 검색 결과에는 공개 회원의 이름과 소개만 나와야 한다.
비공개 회원의 소개는 다른 방문자에게 보여 주면 안 되는 자료다.

최근 식빵두쪽은 검색창에 특정한 값을 넣었더니 비공개 소개까지 보였다는 제보를 받았다.
평범한 이름으로 검색하면 정상적으로 보여서, 어떤 입력이 문제를 일으키는지 확인하려고
검색에 사용된 조건을 화면에 표시해 두었다. 네가 입력한 검색어가 서버에서 어떤 조건으로
바뀌는지, 그 조건으로 어떤 결과가 나오는지 함께 살펴볼 수 있다.

조사용 사이트의 비공개 회원 소개에는 복구 키가 들어 있다. 검색을 통해 이 키를 읽을 수
있다면, 공개 여부를 검사해야 할 검색 기능이 비밀 자료를 노출한 것이다.
식빵두쪽은 그 상황을 직접 재현해 달라고 길드에 의뢰했다.

::objective

검색 입력이 조건에 어떤 영향을 주는지 조사하고, 비공개 회원의 복구 키를 찾아 제출하자.
::

::resources

- 공개 회원 이름은 `mira`와 `sol`이다. 먼저 `mira`를 검색해 이름과 소개가 나오는지 확인해 보자.
- 검색창에는 이름을 입력한다. 아래에서 검색 조건과 결과를 함께 볼 수 있다.
- 비공개 회원은 `public = 0`, 공개 회원은 `public = 1`로 기록돼 있다.
::

::knowledge

SQL은 데이터베이스에 원하는 자료를 요청하는 언어다. 이 사이트에서는 다음 구조로 검색한다.

`SELECT name, note FROM members WHERE name = '입력한 이름' AND public = 1`

- `SELECT name, note`는 이름과 소개를 읽는다.
- `WHERE` 뒤는 결과에 포함할 조건이다.
- `'mira'`처럼 작은따옴표 안의 값은 문자 데이터다.
- `AND`는 양쪽 조건이 모두 참일 때, `OR`는 어느 한쪽이 참일 때 성립한다.

검색 조건에 표시된 입력의 위치와 따옴표를 관찰해 보자. 다음 검색에서는 입력과 결과를 비교하자.
이번 조사에서 필요한 추가 문법은 힌트와 사건 보고서에서 설명한다.
::

::submission
복구 키는 `pwnden{...}` 형식이다. 실행 환경을 새로 준비하면 값이 바뀌므로,
현재 검색 결과에서 찾은 값을 제출하자.
::
