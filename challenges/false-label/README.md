잔비는 문을 닫은 동아리 사이트의 자료를 옮기고 있다. 전달 과정에서 파일 이름이 바뀌었고,
받은 파일에는 `.png` 확장자가 붙어 있다. 그림을 열어 보려는 시도는 실패했다.

이전 담당자는 여러 문서와 복구 키를 한 묶음에 넣었다고 알려 왔다.
잔비는 받은 바이트를 그대로 전달했다. 실제 형식을 확인해 그 묶음에서
복구 키를 찾아 달라는 의뢰다.

::objective
banner.png의 실제 형식을 확인하고, 내부 복구 키를 찾아 제출하자.
::

::resources{title="전달받은 자료"}
배포 파일은 `files/banner.png`다. 텍스트로 표시되지 않는 자료이므로
터미널의 준비된 도구로 앞부분과 구조를 읽을 수 있다.

앞 여덟 바이트를 16진수로 확인하는 명령은 다음과 같다.

```sh
od -An -tx1 -N8 files/banner.png
```

묶음 형식을 알아냈다면 아래 예제의 파일명을 전달 자료로 바꿔 목록을 읽자.
목록에 나온 내부 파일명은 그대로 복사해 쓸 수 있다.

```sh
tar -tzf 묶음파일
tar -xOzf 묶음파일 내부파일명
```
::

### 확장자와 파일의 실제 형식

`.png` 같은 확장자는 파일 이름의 일부다. 파일 이름을 바꿔도 내부 바이트는 그대로다.
실제 형식을 알아보려면 내용의 구조와 앞부분에 있는 식별 바이트를 함께 살펴본다.

PNG 그림의 앞 여덟 바이트는 `89 50 4e 47 0d 0a 1a 0a`다.
gzip 압축 자료는 보통 `1f 8b 08`로 시작한다. 이 값은 바이트를 16진수로 쓴 것이다.
앞부분이 맞는다는 이유만으로 파일 전체가 정상인지는 확정할 수 없다.
그 형식의 도구가 내용을 읽는지도 확인하자.

tar는 여러 파일을 한 자료로 묶고, gzip은 그 묶음의 크기를 줄일 수 있다.
`tar -tzf 파일명`은 gzip으로 압축된 tar 묶음의 파일 목록을 보여준다.
`tar -xOzf 파일명 내부파일명`은 그 파일을 화면에 출력한다. 대문자 `O`가 들어간다.
