# 천 원으로 한정 상품 사기

## 대상과 학습 설계

- 학습 분야: web-security. 주제: web-business-logic.
- 대상: 주소와 웹 폼을 사용할 수 있는 보안 입문자. 난도 2는 기능 간 금액을
  스스로 비교하고 반복 가능한 차이를 찾아야 하는 풀이 부담을 뜻한다.
- 선수 능력: 웹 주소, 요청·응답. 제공된 폼만으로 구매·쿠폰·취소·잔액 확인과 제출을
  수행한다. CLI, 개발자 도구, Python 능력은 요구하지 않는다.
- 학습 목표: 동일 주문의 결제액·환불액·상태를 비교해 기능 사이의 처리 불일치를 입증한다.
- 의뢰인 톱밥은 작업실 상점 운영자다. 시험 계정으로 잔액보다 비싼 한정판을 샀다는
  제보를 재현해 달라고 맡긴다. 제보는 시나리오 설정이며 실제 고객 사고의 주장이 아니다.
- 참고한 패턴: 할인·결제·환불의 업무 로직 결함. PortSwigger의 쇼핑몰 과제에서
  정상 기능을 조합하는 경험을 참고했다. 이 대상은 할인 주문의 환불 차이를 사용한다.

## 판단과 제공 정보

기본 브리핑은 초기 잔액·구매 대상·조사 범위·제출 대상을 제공한다.
상점은 상품 가격, 쿠폰 대상과 재사용 조건, 취소 정책, 실제 결제액과 환불액을
보여 준다. 풀이자는 먼저 정상 동작을 시험하고 할인과 취소를 연결했을 때의 차이를
발견해야 한다. 금액 차이나 반복 절차는 기본 본문과 상점 안내에 노출하지 않는다.
힌트는 과정 비교 → 할인 여부 대조 → 구체적인 차이와 반복 방법 순으로 제공한다.
학습 목표 문서는 문제와 독립적인 금액 예제로 원리를 설명한다.

## 구현과 대조

`vulnerable/app.py`는 쿠키별 Shop을 유지한다. 구매 금액은 서버의 상품 목록과
쿠폰 조건에서 계산한다. 취약한 환불 정책은 `price`, 수정한 정책은 `paid`를 반환한다.
주문과 잔액 변경은 잠금 안에서 처리한다. 재취소는 거부한다. 잔액 부족, 할인 대상
오류, 없는 상품·주문, 잘못된 입력은 결제나 환불을 하지 않는다. 한정판의 결제 완료
주문이 있을 때만 서버가 영수증에 생성된 FLAG를 넣는다. 취소 후 영수증은 노출하지 않는다.
프런트에는 정답이나 자체 결제 판정을 넣지 않는다.

풀이 검증은 초기 한정판 구매 거부, 할인 결제의 500원 차감, 취소 후 500원 증가,
중복 취소 거부, 네 번의 증액, 한정판 구매와 영수증, 별도 계정의 분리를 확인한다.
수정 대조는 풀이가 거부되는 것과 함께 정상·할인 구매 및 취소, 오류 입력, 초기화를
확인한다. 자동 검증은 학습자가 스스로 허점을 찾는지 입증하지 않는다.
