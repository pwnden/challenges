식빵두쪽은 공동 제작실의 종이 창고를 잠시 쓰게 됐다. 게스트는 공개 작업 노트를 읽고,
운영자는 장비 복구 키를 보관한다. 사이트는 방문자가 어떤 등급인지 판단해 자료 접근을 나눈다.

이번에 전달된 복제본에는 브라우저 쿠키를 편집하는 조사용 기능이 붙어 있다.
로그인 세션은 그대로 둔 채, 브라우저가 보내는 등급 표시만 바꿀 수 있다.
식빵두쪽은 게스트로 들어온 사람이 이 표시를 바꿔 운영 자료를 읽을 수 있는지 확인해 달라고 맡겼다.

### Web 요청과 응답 읽기

사이트에서 버튼을 누르거나 주소를 열면 브라우저는 서버에 **요청**을 보내고,
서버는 상태와 내용을 담은 **응답**을 돌려준다. `GET`은 자료 조회에 흔히 쓰이는 요청 방식이다.

예를 들어 `GET /help`는 도움말을 요청한다. 응답의 `200`은 요청 성공,
`403`은 접근 거절, `404`는 찾을 수 없는 자료를 뜻한다. 화면에 오류 안내가 뜨면
입력한 값과 응답 내용을 함께 살펴보자. 상태 번호만으로 자료의 내용까지 알 수는 없다.

**헤더**는 쿠키나 내용 형식 같은 부가 정보다. **본문**은 페이지, 문서, 데이터 자체다.
같은 주소라도 요청에 실린 정보에 따라 서버가 다른 내용을 돌려줄 수 있다.

### 쿠키와 신원

쿠키는 브라우저가 보관했다가 사이트로 다시 보내는 작은 `이름=값` 데이터다.
`theme=dark`처럼 표시 설정을 담기도 하고, 로그인 상태를 이어 가는 데 쓰이기도 한다.

쿠키를 담은 요청은 대략 `Cookie: theme=dark`처럼 보인다. 여기서 `theme`은 이름,
`dark`는 값이다. 값이 `light`로 바뀌면 서버가 받는 요청 정보도 달라진다.

쿠키가 어디에서 왔고 어떤 권한을 나타내는지는 서버가 확인해야 한다.
브라우저가 전달한 글자만으로 그 사용자의 신원과 권한이 증명되지는 않는다.
로그인 세션은 서버가 확인할 수 있는 식별자나 무결성이 검증되는 토큰으로 관리한다.
