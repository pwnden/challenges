::message{from="식빵두쪽"}
제작실 문서 사이트에 게스트로 접속했어요. 브라우저에 저장된 사용자 구분을 바꾸면 운영자 문서도 열릴 것 같아요. 직접 확인해 줄래요?
::

식빵두쪽은 여러 사람이 함께 쓰는 제작실에 초대받았다. 제작실의 문서 사이트에서는
게스트가 공개 작업 노트를 읽고, 운영자가 장비의 복구 키를 확인한다.
복구 키는 장비를 다시 사용할 때 필요한 비밀값이다. 게스트에게 공개되면 안 된다.

브라우저는 이 사이트에 접속할 때 저장된 사용자 구분을 함께 보낸다.
사이트에는 이 값을 바꿔 보는 입력칸이 준비돼 있다. 식빵두쪽은 게스트로 접속한 상태에서
그 값만 바꿔도 운영자의 복구 키를 읽을 수 있는지 확인해 달라고 맡겼다.

::objective
게스트로 접속한 상태에서 운영자의 복구 키를 읽어 제출하자.
::

::resources
웹 도구의 사이트에서 작업 노트와 복구 키 링크를 확인할 수 있다.
처음 사용자 구분은 게스트를 뜻하는 `guest`다. 사이트에 표시된 `paper_role`은
브라우저에 저장된 사용자 구분 값이다. 입력칸에 값을 저장하면 페이지가 다시 열리고
서버가 어떤 사용자로 판단했는지 보인다. 변경 전후 복구 키를 열었을 때의 결과를 비교하자.
::

::knowledge

### Web 요청과 응답 읽기

사이트에서 버튼을 누르거나 주소를 열면 브라우저는 서버에 **요청**을 보내고,
서버는 상태와 내용을 담은 **응답**을 돌려준다. `GET`은 자료 조회에 흔히 쓰이는 요청 방식이다.

예를 들어 `GET /help`는 도움말을 요청한다. 응답의 `200`은 요청 성공,
`403`은 접근 거절, `404`는 찾을 수 없는 자료를 뜻한다. 화면에 오류 안내가 뜨면
입력한 값과 응답 내용을 함께 살펴보자. 상태 번호만으로 자료의 내용까지 알 수는 없다.

**헤더**는 쿠키나 내용 형식 같은 부가 정보다. **본문**은 페이지, 문서, 데이터 자체다.
같은 주소라도 요청에 실린 정보에 따라 서버가 다른 내용을 돌려줄 수 있다.

### 쿠키와 신원

쿠키는 브라우저가 보관했다가 사이트로 다시 보내는 작은 `이름=값` 데이터다.
`theme=dark`처럼 표시 설정을 담기도 하고, 로그인 상태를 이어 가는 데 쓰이기도 한다.

쿠키를 담은 요청은 대략 `Cookie: theme=dark`처럼 보인다. 여기서 `theme`은 이름,
`dark`는 값이다. 값이 `light`로 바뀌면 서버가 받는 요청 정보도 달라진다.

쿠키가 어디에서 왔고 어떤 권한을 나타내는지는 서버가 확인해야 한다.
브라우저가 전달한 글자만으로 그 사용자의 신원과 권한이 증명되지는 않는다.
**세션**은 로그인한 상태를 이어 가기 위한 정보다. 서버에 저장한 사용자 정보를
브라우저의 세션 식별자로 찾아보거나, 서버가 만든 값이 바뀌지 않았는지 검사하는 방식으로 관리한다.
