## 조사 순서

1. 첫 화면에서 서버가 표시하는 등급이 `guest`인지 확인한다.
2. 복구 키를 연다. 서버는 `403`과 staff 등급 안내를 돌려준다.
3. 이전 페이지로 돌아가 쿠키 편집기에 `staff`를 저장한다.
4. 서버 판단이 staff로 바뀐 것을 확인한 뒤 복구 키를 다시 연다.
5. 응답에 나타난 `pwnden{...}` 전체를 제출한다.

## 확인된 원리

바뀐 것은 브라우저의 `paper_role` 주장이다. 서버의 실제 게스트 세션은 그대로다.
취약한 정책은 이 주장을 등급으로 사용해 복구 키 접근을 허용한다.
권한 결정에 쓰는 데이터의 출처와 검증이 중요하다는 것을 관찰했다.

## 고친 동작

패치는 `paper_sid`가 가리키는 서버 세션의 역할을 조회한다. 서버에 저장된 역할은 guest이므로
`paper_role=staff`를 보내도 키 조회는 거절된다. 브라우저의 표시 설정과 실제 접근 권한을
분리하고, 세션 식별자의 유효성을 서버에서 확인해야 한다.

이 실험에는 초대된 게스트 세션과 공개 작업 노트가 준비돼 있다.
로그인 시스템 전체의 설계는 이 문제에서 관찰한 세션 신뢰 경계를 기반으로 확장할 수 있다.
