## 조사 순서

1. 첫 화면에서 서버가 게스트를 뜻하는 `guest`로 판단하는지 확인한다.
2. 복구 키를 연다. 서버는 접근 거절을 뜻하는 `403`과 운영자만 읽을 수 있다는 안내를 돌려준다.
3. 이전 페이지로 돌아가 쿠키 편집기에 `staff`를 저장한다.
4. 서버가 운영자를 뜻하는 `staff`로 판단하는지 확인한 뒤 복구 키를 다시 연다.
5. 응답에 나타난 `pwnden{...}` 전체를 제출한다.

## 확인된 원리

브라우저의 `paper_role`만 guest에서 staff로 바꿨다. 서버에 저장된 사용자는 여전히 게스트다.
하지만 취약한 서버는 브라우저에서 받은 값을 그대로 믿어 운영자의 복구 키를 보여 줬다.
사용자가 바꿀 수 있는 값으로 접근 권한을 결정한 것이 문제다.

## 고친 동작

수정한 서버는 `paper_sid`로 서버에 저장된 사용자 정보를 찾는다. 이 값은 접속 상태를
이어 주는 세션 식별자다. 서버에 저장된 사용자는 guest이므로 `paper_role=staff`를
보내도 키 조회를 거절한다. 접근 권한은 서버가 확인한 사용자 정보로 결정해야 한다.

이 실험에는 초대된 게스트 세션과 공개 작업 노트가 준비돼 있다.
로그인 시스템 전체의 설계는 이 문제에서 관찰한 세션 신뢰 경계를 기반으로 확장할 수 있다.
