# 시나리오 작성 기록

## 시나리오 설정

식빵두쪽은 공동 제작실에 초대된 게스트다. 문서 사이트가 브라우저의 사용자 구분 값만으로 운영자 자료를 보여 주는지 확인해 달라고 맡긴다. 존댓말로 관찰과 요청을 전한다.

- 대표 학습 분야: web-security
- 세부 주제: web-authentication-sessions
- 계약 category: web
- 보안 학습 목표: 브라우저 쿠키의 사용자 구분 값을 바꾸고 서버의 접근 권한 판단을 관찰한다.
- 대상 풀이자: 브라우저 사용과 텍스트 읽기를 할 수 있으며 제공된 조작을 수행하는 사람.
- 플레이어 도구: web. 현재 계약 선언으로 공통 플랫폼 도구를 소비한다.

## 의도된 풀이

1. guest의 키 조회가 403인 것을 확인한다.
2. 같은 세션의 paper_role만 staff로 바꾼다.
3. 서버 등급과 키 조회 성공을 비교하고 동적 복구 키를 제출한다.

## 난도 근거

- 선언: 1 입문 (Intro).
- 브라우저에 준비된 편집기와 두 등급 이름, 요청·응답 설명이 있다. 한 값 변경으로 하나의 신뢰 경계를 관찰한다. 별도 도구 조작과 코드 읽기 없이 시작할 수 있어 입문으로 제안한다.
- 이 평가는 기술 재현과 작성자 검토에 근거한 초안이다. 독립적인 대상 수준 풀이자의 관찰로 재평가한다.

## 다른 풀이와 정답 노출

개발자 도구로 실제 쿠키를 편집하거나 동일한 Cookie 헤더를 보내도 된다. 이 도구 조작은 일반 풀이의 필수 조건이 아니다. 기본 홈과 guest 응답에는 키가 없다. 서버 세션과 HttpOnly 식별자는 그대로 두고 역할 주장만 변경하는 것이 의도된 실험이다.

작성 기록과 풀이 스크립트는 작성자 자료이며 웹의 기본 본문·파일 도구는 선언한
플레이어 자료만 노출한다. 로컬 카탈로그 파일은 비밀 저장소로 취급하지 않는다.

## 검증과 리뷰

- 2026-10-02, Codex 작성·기술 검증. 최초 콘텐츠 구현 작업 트리 기준.
- 실제 HTTP에서 guest 거절, 세션 유지 후 staff 주장 성공, SID 없이 동일한 주장 성공을 확인했다. 패치는 유효한 서버 세션의 역할을 사용하며 guest·위조 SID·빈 쿠키를 거절한다. 단위 검사는 서버가 소유한 guest 세션의 역할 주장이 변조되지 않음을 확인한다. (2026-10-14 정정: 이전에는 "서버가 소유한 staff 세션의 정상 역할도 유지하는지 확인한다"고 적었으나, `vulnerable/app.py`의 `SESSIONS`는 `{SID: 'guest'}` 하나뿐이라 서버가 소유한 staff 세션 자체가 없고 이를 검사하는 테스트도 없다 — 학습 리뷰에서 발견해 바로잡았다.)
- `python3 -B tools/verify.py paper-session`: 고정 Python 3.13.15 이미지에서 풀이와 선언된 패치, 컨테이너·네트워크·볼륨 정리 통과.
- 작성자 내용 검토: 의뢰 맥락, 출발 정보, 완료 조건, 점진적 힌트와 해설의 보안 원리를 대조했다.
- Browser Plugin을 통한 실제 화면 조작 검증은 수행하지 않았다.
- 독립 학습 리뷰: 2026-10-14, 3인 패널로 시작해 controls 항목의 2단계 이상 점수 차이(4 대 2)로 5인으로 확대했다(초급 학습자 관점·증거 검토자·교육 설계자·대안 풀이 검토자·도구·환경 검토자, claude-sonnet-5-5 low effort; 사용자 승인에 따라 스킬이 정한 gpt-6-luna의 대체). 기준표 가중 합산은 controls 조정 반영 후 계산된다. 감사 기록: `quality/panels/paper-session/2026-10-14-panel.json`.
- 리뷰 관찰(확대 사유): 5명 중 3명(judge-2·4·5)이 독립적으로 같은 결함을 찾았다 — `vulnerable/app.py`의 `SESSIONS`에는 'guest' 세션만 있어 서버가 소유한 staff 세션이 아예 없고, `patched/test.py`도 그런 세션이 `/key`에 성공하는 긍정 사례를 검사하지 않는다. AUTHORING.md의 기존 문장("단위 검사는 서버가 소유한 staff 세션의 정상 역할도 유지하는지 확인한다")이 실제 근거보다 넓은 주장이었음을 부모가 소스를 직접 대조해 확인하고, controls를 2점으로 조정했다. 위 "검증과 리뷰" 블록의 문장도 같은 날 정정했다. 다른 항목(goal·starting_context·reasoning·hints·explanation·execution)은 5명 모두 3점 내외로 수렴해 조정하지 않았다.
- 공개 준비: 기술 구현과 학습 리뷰(조정 포함) 모두 마쳤다. 남은 개선 제안(긍정 staff 세션 대조 테스트 추가, 해설의 적용 범위 한계 명시)은 배포를 막는 결함은 아니다. 모델 패널은 실제 입문자 관찰을 대신하지 않으므로, 가능하면 실제 학습자 관찰을 별도로 확보한다.

풀이자는 자료를 읽고 사용할 도구와 비교 기준을 선택한다. 선택형 힌트가 막힌
판단을 돕고, 해설이 재현 명령과 결론을 설명한다. 공통 개념은 학습 연결에서
필요할 때 읽는다. 명령 예제를 기본 본문에 제공했던 기존 설계의 시작 정보·판단·
힌트 평가는 재검토 대기이며, 새 본문에 대한 심사를 완료했다고 간주하지 않는다.

언급하는 과거 기록은 현재 기본 브리핑의 제공 정보로 사용하지 않는다.
