:person[흰돛]은 동아리의 일정 관리 예제 프로젝트를 정리해 공개했다. 팀 복구 키는
구성원을 다시 등록할 때 쓰는 내부 비밀값이라 공개 파일에 넣으면 안 된다.
담당자는 운영 설정 파일을 지우고, 키를 직접 입력하는 공개 예제 파일로 바꿨다.

배포 묶음에는 수정 이력을 관리하는 Git 저장소도 들어 있다. 흰돛은 현재 파일에
키가 없는 것은 확인했지만 과거 이력까지 조사하지는 못했다. 현재 파일과 과거 기록을
비교해, 배포 묶음에서 내부 키를 찾아낼 수 있는지 확인해 달라고 의뢰했다.
설정 파일의 이름 변경과 키 교체도 있었다. 교체 전 키까지 같은 이력에 남을 수
있으므로 이번 배포에 쓰던 키를 구분해야 한다. 저장소는 여덟 커밋의 실습 자료다.

::objective
이번 배포 정보와 이름 변경·키 교체 이력을 연결해, 설정 삭제 직전의 팀 복구 키를 찾자.
::

::resources{title="전달한 소스 묶음"}
- `files/source.tar.gz`: 현재 파일과 `.git` 기록을 포함한 압축 묶음.
- `files/release-note.txt`: 배포 담당자가 수행한 조치와 자료 출처.

아래 명령으로 별도 작업 폴더에 풀고 현재 설정과 이력을 확인할 수 있다.

```sh
mkdir -p work
tar -xzf files/source.tar.gz -C work
cd work/source
ls -a
cat config/example.env
cat config/release.txt
git log --all --stat
```

release.txt는 이번 배포의 버전과 삭제한 운영 설정의 경로를 기록한다.
이력에서 그 경로의 이전 이름과 키 교체를 확인한 뒤 삭제 직전 내용을 읽자.
::

::knowledge

### 준비된 터미널 명령 사용하기

터미널에는 한 줄의 명령을 입력하고 Enter를 누르면 된다. `files/`로 시작하는
경로는 이 문제의 배포 파일을 가리킨다. 명령 예제의 파일명은 조사할 자료의 이름으로 바꿔 넣자.

`printf '%s' 'hello'`는 줄바꿈 없이 `hello`를 출력한다.
`|`는 왼쪽 출력물을 오른쪽 프로그램의 입력으로 전달한다.
예를 들어 `printf '%s' 'hello' | sha256sum`은 정확히 다섯 글자를 해시한다.
`hello` 뒤에 줄바꿈이 추가되면 해시도 달라진다.

각 문제의 ‘전달받은 자료’에서 파일을 읽고 결과를 확인할 명령을 안내한다.
Ctrl+C는 오래 실행되는 명령을 중단하고, 위쪽 화살표는 이전 명령을 다시 가져온다.

### 현재 파일과 Git 이력

파일 이름이 바뀌었다면 `git log --follow -- 경로`로 이전 이름의 이력을 이어서
볼 수 있다. 과거 비밀이 여러 번 바뀌었을 수 있으므로 조사하는 배포 버전과
변경 순서를 비교한다. 현재 파일이 없다는 사실과 이력에 값이 없다는 사실은 다르다.

Git은 파일의 특정 시점 내용을 커밋으로 기록한다. 현재 작업 폴더의 파일을
지워도 과거 커밋에 저장된 내용은 남을 수 있다. 커밋 ID는 그 기록을 가리키는 값이다.

저장소 폴더에서 `git log --all --oneline`을 실행하면 기록과 설명을 읽을 수 있다.
`git log --all --stat`은 변경한 파일 이름도 보여 준다. `git show 커밋ID`는 변경을,
`git show 커밋ID:파일경로`는 해당 시점의 파일 내용을 읽는다. `커밋ID^`는 바로
이전 커밋을 가리킨다. 예제의 ID와 경로는 조사 결과의 실제 값으로 바꿔 넣는다.

파일 묶음을 풀 때는 `mkdir -p 조사폴더`로 작업 폴더를 만든 뒤
`tar -xzf 묶음파일 -C 조사폴더`를 사용한다. `cd 조사폴더/저장소`로 이동한다.
`.git`은 Git 기록을 담은 숨김 폴더다. `ls -a`로 숨김 이름도 볼 수 있다.

`rg '문자열' 파일`은 해당 문자열이 든 줄을 찾는다. 현재 파일과 이력을 각각
확인해야 어느 시점의 값이 배포됐는지 구분할 수 있다.
