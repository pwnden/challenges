# 지운 설정 파일의 이전 내용 작성 기록

## 현재 설명 구성 (2026-10-04)

기본 브리핑에는 상황·목표·범위·접근 정보·자료 위치·제출 대상을 둔다.
풀이자는 자료를 읽고 사용할 도구와 비교 기준을 선택한다. 선택형 힌트가 막힌
판단을 돕고, 해설이 재현 명령과 결론을 설명한다. 공통 개념은 학습 연결에서
필요할 때 읽는다. 명령 예제를 기본 본문에 제공했던 기존 설계의 시작 정보·판단·
힌트 평가는 재검토 대기이며, 새 본문에 대한 심사를 완료했다고 간주하지 않는다.

이하 검토·설계 기록은 작성 당시 버전의 근거다. 본문의 명령 예제나 조작 설명을
언급하는 과거 기록은 현재 기본 브리핑의 제공 정보로 사용하지 않는다.

## 설정과 학습 목표

흰돛은 동아리 예제 프로젝트의 배포 담당자다. 현재 설정을 지운 뒤에도 과거 값이
보인다는 제보를 받고, 자신이 배포한 실제 묶음을 재검증해 달라고 의뢰한다.

- 분야: `software-supply-chain-security`, 주제: `supply-chain-history`, category: `misc`.
- teaches: 현재 파일 삭제와 Git 기록에 저장된 비밀의 제거를 구분한다.
- requires `terminal-commands`, `git-history`: 압축 해제·폴더 이동·이력과 이전 파일
  읽기를 기본 브리핑에 포함한다. Python과 Git 내부 객체 형식은 선수 지식이 아니다.
- 대상과 난도: 준비된 명령을 읽는 초급자, 2 초급. 현재 파일·삭제 커밋·이전 상태를
  연결하는 추론이 필요하며 커밋 ID와 파일 경로는 실제 결과에서 선택한다.

## 자료와 의도된 관찰

1. 공개 예제에는 실제 키가 없고 운영 설정도 현재 checkout에서 사라졌다.
2. 여덟 실제 커밋에 키 교체·파일 이름 변경·삭제가 있다.
3. 배포 정보를 기준으로 삭제 직전의 키를 고르고 이전 키를 제외한다.

`authoring/build.py`는 원격 없는 실제 Git 저장소를 만들고 전체 이력을 압축한다.
Git 저장소를 압축 파일로 배포해 부모 저장소에 의도하지 않은 submodule을 만들지 않는다.
Git 작성자·시간·훅·서명 설정과 tar 메타데이터는 실습용으로 고정한다.
`python3 authoring/build.py`로 배포 파일을 재생성한다.

`authoring/check.py`는 여덟 커밋, 정상 현재 상태, 원격 부재, 현재 키 부재와
과거 키 회수를 실제 Git으로 확인한다. 처음부터 키를 넣지 않은 대조 이력에서는
회수가 실패한다. 자동 해답은 Git·tar·rg만 사용한다.
이름 변경을 실제 Git --follow로 확인하고 삭제 직전에는 교체 후 키만 있음을
검사한다. 이전 키의 제출 digest는 정답과 다르다. 난도 2를 유지하며 배포 정보와
이력의 시간 순서를 비교하는 판단을 추가한다.

## 검증과 리뷰

2026-10-03 Codex 작성. 일반 경로와 `git log --all -p` 대안 경로를 작성자 관점에서
대조했다. 로컬 카탈로그의 작성 자료는 비밀 저장소가 아니며, 공개 본문에는
정답을 노출하지 않는다. 독립 학습자 리뷰와 최종 난도 확인은 배포 전 별도로 수행한다.

Git 대조 검사, 작성자 해답과 소비자 validate·run·verify·stop을 통과했다.
실제 PTY에서 압축 목록 확인·해답·정답/오답 제출·중단·재접속·종료 후 초기화를
검증했고 원본은 보존됐다. 실행 기록은 `authoring/validation.json`에 있다.
