# 시나리오 작성 기록

## 시나리오 설정

- 한 줄 소개와 목소리: 아직안잠이 퇴근 전 발견한 내보내기 기록을 맡긴다. 짧은 반말로 조사해야 할 이상 징후를 전달한다.
- 길드를 찾은 이유: 요청 기록과 감사 기록이 따로 정리돼 있어 실제로 누가 무엇을 받았는지 교차 확인할 사람을 찾았다.
- 플레이어의 역할: 제공된 로컬 대상 또는 배포 자료를 조사하는 길드 조사자.
- 목표와 완료 증거: 성공 상태·요청자·소유자·응답 내용을 같은 요청 ID로 연결해 다른 계정의 자료가 전달된 근거를 제시한다.
- 공개 정보는 README.md, 단계별 발견은 hints/, 완전한 재현은 solve/README.md에 둔다.
- 등장인물은 이번 의뢰의 짧은 설정으로 사용한다. 별도 이야기 저장소의 구조는 후속 설계에서 정한다.

## 학습 목표와 대상

- 계약 category: forensics
- 학습 분야: digital-forensics
- 세부 주제: forensics-event-reconstruction
- 보안 학습 목표: 성공 상태·요청자·소유자·응답 내용을 같은 요청 ID로 연결해 다른 계정의 자료가 전달된 근거를 제시한다.
- 대상 풀이자: 표와 텍스트를 읽는 풀이자. JSON 한 줄의 필드, UTC, HTTP 상태와 요청 식별자는 본문에서 설명한다.
- category 근거: 위 학습 주제를 현재 계약의 가장 가까운 분류로 표시한다.
- 도구: files. 이 선언으로 기존 플랫폼 공통 기능을 소비한다.

## 선수 지식과 학습 내용

시작 능력은 브라우저 사용과 텍스트 입력·읽기다. 이번 문제에서 필요한 추가 용어와
조작은 README.md의 전달받은 정보와 시작 전 알아둘 것에서 설명한다.
프로그래밍 언어 문법을 읽거나 코드를 작성하는 능력을 풀이의 선수 조건으로 두지 않는다.

## 의도된 풀이

| 단계 | 행동 | 관찰 | 필요한 지식·도구 |
| --- | --- | --- | --- |
| 1 | 요청 로그에서 guest의 성공 요청을 찾는다 | req-202와 req-205 | 파일 도구, 상태 코드 설명 |
| 2 | 같은 ID의 감사 기록을 찾는다 | 자료 소유자와 실제 응답 | 식별자 비교 |
| 3 | 요청자와 소유자를 비교한다 | req-205의 다른 계정 자료 전달 | 계정별 자료 소유 개념 |
| 4 | 그 응답의 키를 읽는다 | 해당 사건의 복구 키 | 기록된 증거 읽기 |

대상 구현과 자동 검증에는 Python을 사용한다. 풀이자가 사용할 경로와 도구는 위 표를 따른다.

## 개념 관계

선수 능력과 새로운 학습 목표를 위에서 구분한다. 재사용 개념 선언과 그래프 API는
현 계약에 없으므로 이번 자료는 본문 안에서 읽을 수 있는 배경 설명으로 제공한다.
분야·세부 주제의 의미는 [학습 지도](../../docs/learning-map.md)를 따른다.
구체적인 공격 식과 정답은 추가 정보와 사건 보고서에서 공개한다.

## 난도 근거

- 선언한 값: 1 Intro
- 전체 풀이 부담: 각 파일 6건이며 필요한 필드와 상태를 본문에서 설명한다. 한 식별자로 두 기록을 연결하고 코딩·로그 도구 사용·큰 자료 탐색이 없다. Easy의 불완전하거나 충돌하는 증거 해석은 요구하지 않는다.
- 구현 부담: 준비된 도구의 입력과 자료 관찰. 풀이 코드 구현은 요구하지 않는다.
- 등급은 아래의 독립 학습 리뷰 결과에 따라 재검토한다.

## 다른 풀이와 정답 노출

자료를 내려받아 같은 ID를 검색할 수 있다. 정상 내보내기에도 다른 복구 키가 있어 후보 문자열만 찾는 방법으로 정답을 확정할 수 없다. 감사 기록은 역순으로 배포한다.

풀이자에게 필요한 사전 설명은 기본 브리핑에 둔다. 로컬 카탈로그의 작성자 파일은
비밀 저장소로 취급하지 않으며, 사이트의 기본 파일 도구에는 배포 자료만 선언한다.

## 검증과 리뷰

- 실행 범위: authoring/capture.py가 루프백 실험 HTTP 서버에서 실제로 발생시킨 여섯 교환의 기록이다. 서로 다른 계정과 소유자, 공개 레거시 경로와 보호된 경로를 명시한 학습용 실험이며 실제 침해 사건 자료로 주장하지 않는다.
- 기술 확인 범위: 배포 파일의 ID 일대일 대응, 성공·거부·없는 자료 상태, 단 하나의 게스트 타인 소유 자료 노출, 파일 정렬을 바꿔도 같은 정답, 오답 키 해시 거절을 확인한다.
- 기술 검증: 2026-10-02, 이 파일을 포함한 최초 콘텐츠 제출 버전. 호스트 Python 3.14.7, 풀이 이미지 Python 3.13.15, Docker 29.4.1, Compose 5.1.3에서 형식 검사, 전체 6개 문제 풀이·선언된 패치·정리 검사와 47개 회귀 검사를 통과했다.
- 격리 검증: 도달 가능한 대조군을 확인한 뒤 외부 IPv4·IPv6·DNS, 호스트와 별도 문제 네트워크 접근 차단, 같은 문제 내부 HTTP 성공 및 대조군 정리를 확인했다.
- 내용 검토: Codex가 초기 사용자 관점으로 배경·단계별 단서·해설·정답 노출을 검토했다. 독립 학습 리뷰와는 구분한다.
- 독립 학습 리뷰: 대상 수준 풀이자의 실제 리뷰는 아직 수행하지 않았다.
- 공개 준비 상태: 기술 검증과 별도로 독립 학습 리뷰와 난도 확인을 마친 뒤 공개한다.
