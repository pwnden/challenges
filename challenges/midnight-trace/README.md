> “퇴근하려고 로그를 열었는데, 내보내기 기록이 걸렸어. 이거 확인하고 자야겠네.”

아직안잠이 자료 내보내기 사이트의 기록 두 벌을 보내왔다.
사이트에서는 각 계정이 자기 자료를 내보낼 수 있다. 게스트가 운영 계정의 자료를 가져간 흔적을 찾아 달라는 의뢰다.

## 의뢰 목표

게스트가 다른 계정의 자료를 받아 간 요청을 찾고, 그 응답에 담긴 복구 키를 제출하자.

## 전달받은 정보

- `files/access.log`: 요청한 계정, 주소와 서버 응답 상태.
- `files/audit.jsonl`: 자료 소유자와 실제 응답 내용.
- 두 파일은 로컬 실험 사이트에서 실제 요청·응답을 기록한 학습용 자료다.
- 게스트 계정은 `guest`, 운영 계정은 `ops`다.

## 시작 전 알아둘 것

파일 도구에서 두 자료를 바로 읽을 수 있다. 한 줄마다 하나의 기록이 들어 있다.

| 필드 | 읽는 방법 |
| --- | --- |
| `timestamp` | 기록 시각. `+00:00`은 UTC 시간대를 뜻한다. |
| `request_id` | 같은 요청을 두 기록에서 연결하는 식별자. |
| `user` | 자료를 요청한 계정. |
| `owner` | 해당 자료의 소유 계정. |
| `status` | 서버 응답 상태. `200`은 성공, `403`은 접근 거부, `404`는 자료 없음. |
| `response` | 실제로 요청자에게 전달한 내용. |

파일마다 기록을 정리한 순서가 다르다. `request_id`가 같은 기록을 연결해 보자.
성공한 요청에서 요청자와 자료 소유자가 누구인지 확인하자.

복구 키는 `pwnden{...}` 형식이다.
