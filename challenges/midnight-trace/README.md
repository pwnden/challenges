::message{from="아직안잠"}
게스트가 운영 계정 자료를 받아 간 것 같아. 요청 기록은 있는데, 그때 실제로 뭘 받았는지까지 확인해 줄래?
::

사이트 기록을 정리하던 :person[아직안잠]에게서 의뢰가 도착했다. 조사할 대상은 계정별로
자료를 보관하는 웹사이트다. 사용자는 ‘내보내기’ 기능으로 자신이 보관한 자료의
사본을 받아 갈 수 있다. 자료에는 계정을 복구할 때 쓰는 비밀값인 복구 키도 들어 있어, 다른 사람에게 전달되면
비밀값이 함께 노출된다.

이 사이트에는 게스트 계정 `guest`와 운영 계정 `ops`가 있다. 두 계정은 각자 소유한
자료만 받아 갈 수 있어야 한다. 그런데 아직안잠은 게스트의 요청 가운데 운영 계정의
자료에 접근한 듯한 기록을 발견했다. 접근을 시도한 것인지, 실제 자료까지 받은 것인지
확인하려고 당시 기록을 길드에 맡겼다.

아직안잠이 보낸 `access.log`에는 요청 기록이, `audit.jsonl`에는 서버가 보낸 내용의
기록이 남아 있다. `access.log`에서 **누가 요청했는지**, `audit.jsonl`에서
**누구의 자료를 어떤 내용까지 보냈는지** 확인할 수 있다. 두 기록을 함께 읽어 그때 있었던 일을 밝혀 보자.

::objective

게스트 `guest`가 운영 계정 `ops`의 자료를 실제로 받아 간 요청을 찾자.
그 요청에서 게스트에게 전달된 복구 키를 제출하면 의뢰가 완료된다.
::

::resources

| 자료 | 무엇을 확인할 수 있나 |
| --- | --- |
| `files/access.log` | 어떤 계정이 어느 주소로 요청했고, 서버가 성공 또는 거부로 처리했는지 |
| `files/audit.jsonl` | 요청한 자료의 소유 계정과 서버가 요청자에게 실제로 보낸 내용 |

두 파일은 같은 여섯 번의 요청을 서로 다른 관점에서 기록했다. 정상적인 내보내기와
거부된 요청도 섞여 있다. 복구 키가 여러 개 보이므로, 목표에 해당하는 요청의 값을 골라야 한다.
이 자료는 실험용 사이트에서 실제 요청과 응답을 발생시켜 만든 학습용 기록이다.
::

::knowledge

파일 도구에서 먼저 `files/access.log`를 열어 보자. 첫 줄의 `#`로 시작하는 문장은
자료에 대한 안내다. 그 아래에서는 한 줄이 하나의 요청 기록이고, 각 줄의
`"필드 이름": 값`이 그 요청의 정보를 나타낸다. `files/audit.jsonl`도 같은 방식으로 읽는다.

| 필드 | 읽는 방법 |
| --- | --- |
| `timestamp` | 기록 시각. `+00:00`은 UTC 시간대를 뜻한다. |
| `request_id` | 같은 요청을 두 기록에서 연결하는 고유 번호. |
| `user` | 자료를 요청한 계정. |
| `owner` | 해당 자료의 소유 계정. |
| `path` | 요청한 주소의 경로. 어떤 자료를 받으려 했는지 나타낸다. |
| `status` | 서버 응답 상태. `200`은 성공, `403`은 접근 거부, `404`는 자료 없음. |
| `response` | 서버가 요청자에게 보낸 내용. 복구 키나 오류 메시지가 들어 있다. |

예를 들어 `user`가 `guest`이고 `owner`도 `guest`라면 게스트가 자기 자료를 요청한 것이다.
`status`가 `403`인 요청은 서버가 거부한 시도다. 어떤 요청에서 실제 자료가 전달됐는지
판단하려면 응답 상태와 `response`의 내용을 함께 확인해야 한다.

파일마다 기록 순서가 다르다. 같은 요청은 두 파일에서 같은 `request_id`를 갖는다.
이 값을 기준으로 요청 기록과 응답 내용을 연결해 보자.
::
