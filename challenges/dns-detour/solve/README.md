## 조사 순서

1. dns.jsonl에서 Q 메시지이며 qname이 sync.box.test로 끝나는 기록을 찾는다.
2. 1-과 2- 뒤의 문자 조각을 적는다. 먼저 관찰되는 것은 2번일 수 있다.
3. 동일한 2번 재전송은 하나로 합친다. 응답 R도 같은 이름을 되풀이한다.
4. 1번 조각 다음에 2번 조각을 이어 붙인다.
5. 준비된 base32 --decode 명령에 이 40글자를 전달한다.
6. `pwnden{dns_leaks_data_ok}`를 제출한다.

실제 연결 문자열은 아래와 같다.

```sh
printf '%s' 'OB3W4ZDFNZ5WI3TTL5WGKYLLONPWIYLUMFPW6235' | base32 --decode
```

## 확인된 원리

DNS 조회 요청에는 프로그램이 찾는 이름이 들어간다. 이 이름에 자료를 문자로 바꿔 붙이면
DNS 서버도 그 자료를 받는다. 이번 기록에서는 번호로 순서를 맞추고 Base32를 되돌려
그 내용을 확인했다. 서버가 요청을 받았다면 응답이 실패해도 조회 이름은 이미 전달된 것이다.

이번 자료는 한 컴퓨터 안에서 실제 DNS 요청과 응답을 주고받아 만든 학습용 기록이다.
실제 사고를 조사할 때는 어떤 프로그램이 어느 서버로 요청했는지와 다른 통신 기록도 확인한다.
허용할 DNS 서버를 정하고 조회 이름을 기록하면 이런 전송을 제한하고 조사하는 데 도움이 된다.
