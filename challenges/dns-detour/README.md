이상한 동기화 도구가 조회하는 이름을 봤더니 주소 같지가 않아. 이름 안에 데이터를 넣어 보낸 것 같아서, 어떤 값인지 복원해 줬으면 해.
::

아직안잠은 설치했던 동기화 도구의 동작을 조사하고 있다. 도구는 정상적인 사이트 이름도
조회하지만, `sync.box.test` 앞에는 긴 문자 조각을 붙여 DNS 질의를 보낸다.
DNS는 이름에 해당하는 주소 정보를 묻는 방식이라 질의 자체에도 이름이 실린다.

전달된 기록은 이 동작을 로컬 실험에서 재현해 실제 UDP 질의와 응답을 수집한 것이다.
질의 이름의 맨 앞에는 `1-` 또는 `2-`라는 조각 번호가 있다.
두 조각은 한 값을 나눠 보낸 것이며, 재전송 때문에 같은 조각이 반복될 수 있다.

::objective
DNS 질의 이름에 실린 데이터 조각을 복원해, 전송된 값을 제출하자.
::

::resources{title="전달받은 자료"}
`files/dns.jsonl`의 각 줄은 메시지 하나다. `direction`은 질의 Q 또는 응답 R,
`id`는 메시지 ID, `qname`은 실제 질의 이름이다.

`sync.box.test`로 보낸 질의에서 번호 뒤의 두 문자 조각을 찾자.
번호 순서로 붙인 문자열을 아래 예제의 `문자열` 자리에 넣으면 복원할 수 있다.

```sh
printf '%s' '문자열' | base32 --decode
```

현재 자료에서는 두 조각을 합친 값에 padding 문자 `=`를 붙일 필요가 없다.
::

::knowledge

### DNS 질의 기록 읽기

DNS는 이름에 해당하는 정보를 묻고 응답하는 프로토콜이다.
`www.example.test`의 `www`, `example`, `test`처럼 점으로 나뉜 부분을 **라벨**이라고 한다.
DNS 질의에는 묻는 이름과 질의 종류가 들어간다. `A`는 IPv4 주소를 묻는 종류다.

이 자료의 `Q`는 질의, `R`은 응답이다. 같은 메시지 ID로 요청과 응답을 짝지을 수 있다.
같은 질의가 재전송되면 같은 이름이 기록에 여러 번 나타날 수 있다.
시간 순서와 데이터 조각의 순서는 서로 다를 수 있으므로 기록의 번호와 이름을 함께 보자.

도메인 이름에는 주소 조회 이외의 데이터도 실릴 수 있다. 그 이름을 받는 DNS 서버는
질의에 들어간 라벨을 볼 수 있다. 응답 성공 여부와 질의 데이터가 전달됐는지는 구분해서 판단한다.

### Base32로 적힌 데이터

Base32는 바이트를 `A`부터 `Z`와 `2`부터 `7`까지의 문자로 나타내는 공개 규칙이다.
숫자 `0`과 `1`은 이 알파벳에 포함되지 않는다. 다른 비밀 키 없이 원래 바이트로 복원할 수 있다.

`hello`는 Base32에서 `NBSWY3DP`다. 준비된 터미널에서 아래처럼 확인할 수 있다.

```sh
printf '%s' 'NBSWY3DP' | base32 --decode
```

길이에 따라 마지막에 `=`가 붙을 수 있다. 이번 문제 자료는 `=`가 필요 없는 길이로 만들었다.
조각으로 나뉜 문자열은 순서대로 붙인 뒤 한 번에 복원한다.
