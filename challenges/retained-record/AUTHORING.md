# 삭제한 문서가 남은 백업 작성 기록

## 설정과 설계

도토리장은 작업 보드의 문서 담당자다. 목록에서 문서가 사라진 뒤 삭제 안내를
보내기 전에, 같은 시점의 실제 백업도 조사해 달라고 의뢰한다.

- 분야: `digital-forensics`, 주제: `forensics-event-reconstruction`, category: `forensics`.
- teaches: 목록 필터·문서 상태와 본문 보관을 구분해 백업의 공개 범위를 확인한다.
- requires `terminal-commands`, `sqlite-records`: 테이블·열·ID·조건·연결·버전 순서의
  범위만 브리핑에 설명한다. Python과 디스크 포렌식은 선수 지식이 아니다.
- 대상: 안내된 SQL 문법으로 표를 읽는 초급자. 난도 2 초급을 제안한다.
  목록·상태·변경 본문을 연결하며 쿼리와 버전 선택이 입문보다 한 단계 더 필요하다.

## 자료와 관찰

`authoring/build.py`는 실제 SQLite에 문서와 버전을 저장하고 문서 26을 삭제
상태로 바꾼 뒤 화면용 목록을 조회한다. DB와 CSV는 같은 상태에서 나온다.
`python3 authoring/build.py`로 재생성한다. 네 문서·여섯 본문으로 범위를 제한한다.

1. 화면용 목록은 active 두 문서만 담는다.
2. 삭제 문서가 둘이고 대상 문서에는 승인본과 더 최신인 초안이 남는다.
3. 제목과 승인 상태를 고른 뒤 마지막 승인 버전의 코드를 회수한다.

`authoring/check.py`는 실제 sqlite3 조회, CSV와 active 행 일치, 재생성한 구조·내용,
제출 해시를 확인한다. 해당 본문을 제거하고 VACUUM한 대조 DB에서는 회수에 실패한다.
이는 파일의 미할당 영역 복구 문제가 아니다. JOIN 대신 ID로 두 번 조회하는
대안 풀이도 유효하다. 원본은 `-readonly`로 읽는다.
추가 대조는 전체 삭제 문서의 최대 버전과 대상 문서의 최신 초안이 올바른
코드를 내지 못함을 확인한다. 버전 정렬 전에 대상과 승인 상태를 판단해야 한다.

자료 대조·본문 제거 대조군, 작성자 해답과 소비자 validate·run·verify·stop을 통과했다.

검증했다. 실행 기록은 `authoring/validation.json`에 있다.
