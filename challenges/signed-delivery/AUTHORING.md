# 서명이 맞는 납품 문서 작성 기록

## 목표와 선수 능력

온전한서명은 납품 수신 담당자다. 항목이 다른 사본 중 승인 원문을 골라야 하며
발신자에게 확인한 공개키와 서명을 제공한다.

- 분야 `cryptographic-security`, 주제 `crypto-public-keys-signatures`, category `crypto`.
- teaches: 신뢰한 공개키의 서명 검증으로 내용 변경을 구분한다.
- requires `terminal-commands`, `detached-signatures`: 공개키·분리 서명·검증 성공/
  실패·정확한 바이트의 해시·제출 형식은 브리핑에서 설명한다.
- 대상은 준비된 명령을 조정하는 초급자다. 난도 2는 여러 사본의 검증 결과와
  원문 해시를 연결하는 판단에 근거한다. 수학·개인키 생성·Python은 필요 없다.

## 자료 출처와 관찰

`authoring/build.py`는 고정 문서와 길이가 같은 변경 사본 두 개를 만든다.
임시 디렉터리에서 RSA-2048 개인키를 생성해 PKCS#1 v1.5/SHA-256으로 서명하고
공개키·서명만 배포한 뒤 개인키와 디렉터리를 삭제한다. 실제 업무 키는 없다.
생성 사본의 시각은 동일하게 설정한다. 파일명은 원문을 표시하지 않는다.

1. 신뢰한 키와 서명의 역할을 확인한다.
2. OpenSSL로 세 사본을 검증해 원문 하나만 통과함을 확인한다.
3. 원문 바이트의 SHA-256으로 제출값을 만든다.

`authoring/check.py`는 실제 OpenSSL 검증으로 원문·변조 사본을 구분한다.
추가 1바이트 변경·서명 1바이트 변경·다른 공개키의 실패와 자료 재생성 후
같은 원문의 통과를 확인한다. 개인키 부재·native sha256sum과 제출 digest도
검사한다. 문서에는 정답 문자열을 넣지 않는다. 해답은 CLI만 사용하고
검증한 사본이 정확히 하나일 때만 해시를 출력한다. 수동 후보 비교도 유효하다.
