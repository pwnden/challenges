## 조사 순서

1. account.txt에서 계산 방식이 SHA-256인지 확인한다. UTF-8은 글자를 바이트로
   나타내는 방식이며, salt=none은 계산에 추가 값을 넣지 않았다는 뜻이다.
   password_hash가 비교할 결과다.
2. 후보마다 `printf '%s' '후보' | sha256sum`을 실행한다.
3. 출력의 해시가 저장된 값과 일치하는 후보를 찾는다.
4. 일치하는 비밀번호는 `pwnden{rainboat27}`이다. 이 값을 그대로 제출한다.

출력이 다르면 후보 철자, 대소문자와 줄바꿈을 확인하자.
`echo`를 그대로 사용하면 줄바꿈까지 입력에 포함될 수 있다.

## 확인된 원리

후보 여섯 개를 각각 계산해 저장된 값과 비교하자 맞는 비밀번호를 찾을 수 있었다.
이렇게 후보를 하나씩 시험하는 방법을 **사전 대입 공격**이라고 한다.
SHA-256처럼 빠른 계산을 한 번만 적용하면 많은 후보도 빠르게 비교할 수 있다.

## 보호 방법

비밀번호는 후보 하나를 계산하는 데 시간이 들도록 설계된 전용 방식으로 저장한다.
사용자마다 다른 추가 값인 **salt**도 함께 계산한다. 그러면 같은 비밀번호를 쓰는 계정도
서로 다른 결과를 갖고, 미리 계산해 둔 목록을 여러 계정에 그대로 적용하기 어려워진다.
비밀번호 자체도 추측하기 어렵게 정하고, 로그인 시도 횟수를 제한해야 한다.
