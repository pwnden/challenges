## 시나리오 설정

- 표시 제목: 야간 진단 콘솔의 메모 기능

- 한 줄 소개: 야간 진단 콘솔 관리자가 타이핑으로는 닿을 수 없는 운영진 전용 기록을 메모 기능으로 끌어낼 수 있는지 확인해 달라고 의뢰한다.
- 공개 닉네임과 말투: 야간당직. 자신이 관리하는 콘솔의 두 입력(명령·메모)과 각각의 범위를 정확히 설명하고, "안전하다고 생각했는데"라며 확신이 흔들린 지점을 솔직히 말한다.
- 의뢰인과 플레이어의 역할: 야간당직은 콘솔 관리자, 플레이어는 명령·메모 두 입력을 함께 시험하는 조사자다.
- 대상과 사건의 계기: 야간 진단 콘솔 프로그램(STATUS 명령, 메모 저장 기능, 타이핑으로는 닿지 않는 운영진 전용 기록 처리 경로). 메모 입력으로 그 경로를 간접 실행시킬 수 있다는 이야기.
- 길드를 찾은 이유: 야간당직은 명령 칸이 짧아 안전하다고만 생각했고, 메모 쪽의 메모리 동작까지는 분석하지 못했다.
- 이번에 공개할 정보: 컴파일된 프로그램 파일과 접속 주소, 명령·메모 두 단계 프로토콜. 복귀 주소, 레지스터, 함수 이름 같은 용어는 공개하지 않는다.
- 의뢰 목표와 완료 증거: 메모 입력만으로 운영진 전용 기록(현재 flag)을 끌어냄. 새 연결에서 STATUS 명령 뒤 메모 하나만으로 성공해야 한다.
- 처음 전달할 사실: 호스트·포트, 프로그램 파일, 명령·메모 두 단계 프로토콜.
- 사건의 흐름: 평소 동작(명령 칸은 STATUS만 의미 있고 짧아서 긴 명령은 타이핑 불가, 메모는 저장만 함) → 제보(메모로 그 긴 명령을 간접 실행시킬 수 있다는 이야기) → 야간당직이 직접 확인하지 못함 → 조사 권한(프로그램 파일·접속 주소) 전달 → 실제로 운영진 전용 기록까지 닿을 수 있는지 조사.
- 조사 중 발견할 사실: 메모가 선언된 크기보다 긴 값을 받아들인다는 것, 그 초과분이 저장된 복귀 위치까지 닿는다는 것, 복귀 위치만으로는 인자가 필요한 함수를 부를 수 없다는 것, 레지스터를 먼저 설정하는 짧은 코드 조각이 실행 파일 안에 있다는 것.
- 풀이자에게 남긴 판단: 메모의 실제 한계를 시험할지 여부, 오프셋 계산, 어느 코드 조각과 어느 함수를 어떤 순서로 이을지.
- 학습 목표와의 연결: 입력 칸이 짧아 타이핑으로 못 넣는 값도 메모리 쓰기 결함과 기존 코드 조각을 조합하면 전달할 수 있다는 것을, 인자가 필요한 함수 호출의 구성을 통해 직접 관찰한다.

## 학습 목표와 대상

- 현재 계약의 category: "pwn"
- 학습 분야: System security(`learning-map.md`) 중 `pwn-control-flow` — "Redirect a writable callback to a supplied target function; then saved return addresses and constructed call sequences"의 후반부(구성된 호출 연쇄)에 해당한다.
- 세부 주제: `pwn-control-flow`.
- category 선택 근거: 저장된 복귀 주소를 레지스터 설정 조각과 대상 함수로 이어 붙여 인자가 있는 호출을 구성하는 문제로, `greeting-echo`(인자 없는 복귀 주소 변조)의 다음 단계다.
- 보안 학습 목표: 복귀 주소를 임의 함수의 주소로 덮어쓰는 것만으로는 인자가 필요한 호출을 재현할 수 없고, 레지스터를 먼저 설정하는 짧은 코드 조각을 거쳐야 한다는 것, 그리고 입력 칸이 짧아 특정 값을 타이핑으로 못 넣는 것이 그 값을 다른 경로로도 전달할 수 없다는 뜻은 아니라는 것을 설명할 수 있다.
- 확인할 보안 원리: 메모리 쓰기 결함과 기존 코드 조각을 조합한 인자 있는 함수 호출 구성(`pwn-control-flow`).
- 대상 풀이자: `greeting-echo`에서 다진 복귀 주소 변조(`return-address-control`)에 더해, `nm`·`objdump`로 코드 조각과 함수·문자열의 실제 주소를 찾아 순서대로 연결할 수 있는 풀이자. 디버거 사용은 요구하지 않는다.
- 시작 조건과 성공 증거: 프로그램 파일과 접속 주소가 주어진다. 메모 입력만으로(명령 칸에 직접 타이핑하지 않고) 운영진 전용 기록에서 현재 flag를 읽으면 성공이다.

## 의도된 풀이

| 단계 | 풀이자가 수행할 행동 | 발견·관찰할 내용 | 필요한 지식·도구 |
| --- | --- | --- | --- |
| 1 | "SHOW-ADMIN-LOG"를 명령 칸에 직접 입력해 본다 | 명령 칸이 너무 짧아 "알 수 없는 명령입니다"로만 처리됨 | 본문 |
| 2 | 메모에 점점 긴 값을 보내 본다 | 64바이트를 넘으면 비정상 종료로 바뀌는 경계 발견 | 힌트 1 |
| 3 | `objdump -d -M intel files/console`로 `main`과 `run_command`를, `nm`으로 전체 심볼을 읽는다 | 메모 버퍼(rbp-0x60)와 복귀 위치의 오프셋(104), `pop_rdi_ret`·`run_command`의 실제 주소, "SHOW-ADMIN-LOG" 문자열의 실제 주소 | 힌트 2, `return-address-control` |
| 4 | 104바이트 채움 + `pop_rdi_ret` 주소 + 문자열 주소 + `run_command` 주소로 메모를 보낸다 | "관리자 기록: pwnden{...}" | 힌트 3, 해설 |

보안 학습 목표와의 연결: 1단계는 "짧은 입력 칸이 그 값 자체를 막지는 않는다"는 질문을 세우고, 2~4단계는 메모리 쓰기 결함 + 기존 코드 조각 조합으로 그 값을 간접 전달하는 전체 과정을 재현하게 한다.

풀이자의 언어 지식: 코드 작성은 필요 없다. `objdump`·`nm` 출력에서 세 개의 주소와 한 개의 오프셋을 읽어 정해진 순서로 이어 붙이는 바이트 조합만 필요하다.

## 개념 관계

- 문제의 선수 개념: `return-address-control`(`greeting-echo`가 가르침), `tcp-services`, `terminal-commands`.
- 문제의 학습 개념: `argument-call-chains`(`knowledge/argument-call-chains.md`) — 인자를 설정한 뒤 이어 부르는 함수 호출.
- 개념 간 선수 관계: `argument-call-chains`는 `return-address-control`을 선수로 한다. 순환 없음.
- 관련 읽기: `greeting-echo`(같은 pwn 계열의 이전 단계, 인자 없는 복귀 주소 변조만 다룬다).
- 공개 위치: 프로그램 파일과 두 단계 프로토콜은 본문에서 공개. 정확한 오프셋·조각 이름·함수 이름은 힌트·해설에서만 명시한다.

## 난도 근거

- 선언한 값: 4 (1 입문, 2 초급, 3 중급, 4 고급, 5 심화)
- 선수 지식 부담: `return-address-control`(이전 문제에서 다짐) 위에 레지스터 설정 조각과 다단계 호출 연쇄라는 새 개념을 더한다.
- 발견 난도: 명령 칸의 한계 확인 → 메모 경계값 시험 → 두 개의 오프셋/주소 계산(버퍼-복귀 위치, 조각-문자열-함수) → 세 값을 올바른 순서로 연결, 총 네 단계이며 각 단계가 이전 문제(난도 3)보다 한 겹 더 많은 조합(레지스터 설정)을 요구한다.
- 구현 부담: 코드 작성 없이 세 개의 8바이트 주소를 정해진 순서로 이어 붙이는 스크립트가 필요하다.
- 풀이 의존성: 3단계(오프셋·주소 확인)가 4단계(연쇄 구성)의 전제이며, 틀린 순서나 틀린 주소는 비정상 종료로 즉시 드러난다.
- 등급 판정: `greeting-echo`(난도 3, 인자 없는 단일 주소 덮어쓰기)보다 한 단계(레지스터를 먼저 설정해야 하는 다단계 호출 연쇄) 더 복잡해 난도 4가 적절하다.

manifest의 difficulty를 바꾸면 이 기록도 함께 갱신하세요.

## 다른 풀이와 정답 노출

- 확인한 다른 풀이: 디스어셈블리 없이 메모 길이를 점점 늘려 가며 비정상 종료 경계(64바이트)를 먼저 찾는 블랙박스 풀이도 동일한 결론(메모가 복귀 위치까지 닿는다)에 이르지만, 주소 세 개는 결국 `nm`·`objdump` 없이는 알 수 없어 화이트박스 분석이 필수다.
- 의도치 않은 지름길 점검: "SHOW-ADMIN-LOG"를 명령 칸에 직접 입력하면 7글자로 잘려 절대 일치하지 않음을 확인했다(의도한 설계). 메모 응답에는 정답 형식의 고정 문자열이 없다.
- 본문 노출 점검: 본문은 프로그램 파일과 두 단계 프로토콜만 제공하고, 메모가 복귀 위치에 닿는다는 것이나 필요한 코드 조각은 말하지 않는다. 파일을 그대로 실행하거나 짧은 메모만 보내서는 목표에 도달할 수 없다.
- 필요한 힌트: 1번은 메모 한계 시험, 2번은 오프셋·대상 함수를 찾는 도구(objdump, nm), 3번은 레지스터 설정 조각을 이용한 연쇄 구성 방법을 각각 제공한다. 본문만으로는 인자가 필요한 함수 호출이라는 점을 알 단서가 부족해 3개를 유지한다.
- 해설: `solve/README.md`에 오프셋·주소 확인, 호출 연쇄 구성, 실제 성공, 패치 뒤 동작까지 기록했다.

## 검증과 리뷰

- 실행 범위: 실제 대상. 컴파일된 `files/console`을 직접 실행해 명령 칸이 "SHOW-ADMIN-LOG"를 담지 못함과 메모 경계(64바이트)를 확인했고, 실제 TCP 서비스(`docker compose`)에 대해서도 같은 호출 연쇄가 매번 성공함을 확인했다. `tools/verify.py night-console`로 취약한 서버에서 solve가 flag를 회수하고 패치 서버에서는 거부됨을 확인했다.
- 기술 검증: 2026-10-14, `objdump`·`nm`으로 확인한 오프셋(메모 버퍼=rbp-0x60, 복귀 위치까지 104)과 세 주소(`pop_rdi_ret`=0x401248, 문자열=0x40201e, `run_command`=0x401196)가 실제 공격 성공과 일치함을 확인했다. 컴파일에 쓰는 Debian 패키지 스냅샷을 `vault-gate`·`greeting-echo`와 같은 방식으로 고정해 주소가 빌드마다 바뀌지 않음을 확인했다. 연결을 받는 Python 계층이 첫 줄을 버퍼링된 스트림으로 읽은 뒤 이어지는 메모를 raw 소켓으로 읽으면, 클라이언트가 두 메시지를 한 번에 보낼 때 뒤쪽 바이트가 버려지는 결함을 발견해 모든 읽기를 같은 버퍼링된 스트림으로 통일했다(이 결함은 응답을 기다린 뒤 보내는 클라이언트에서는 드러나지 않았다). `tools/verify.py night-console` 통과. `patched/test.py`가 평소 사용·미지원 명령·경계값(64바이트)·이전 ROP 연쇄 메모를 모두 확인한다.
- 학습 리뷰: 2026-10-14, 3인 패널(초급 학습자 관점·증거 검토자·교육 설계자, claude-sonnet-5-5 low effort; 사용자 승인에 따라 스킬이 정한 gpt-6-luna의 대체). 기준표 가중 합산 75.0/100. `needs_adjudication` 없음, 5인 확대 조건 미충족. 감사 기록: `quality/panels/night-console/2026-10-14-panel.json`.
