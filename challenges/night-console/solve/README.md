## 조사 결과

명령 칸(`cmd[8]`)은 "SHOW-ADMIN-LOG"(14글자)를 타이핑으로 담기에는 너무
짧아 직접 입력할 방법이 없다. 하지만 메모 입력은 선언된 64바이트를 넘는
값을 그대로 받아들여, 그 초과분으로 저장된 복귀 위치를 덮어쓸 수 있다.
`run_command`는 인자(문자열 주소)를 받아야 동작이 갈리는 함수이므로,
복귀 위치만으로는 부족하다. 실행 파일 안에 있는 `pop_rdi_ret`라는 두
줄짜리 코드 조각으로 먼저 인자를 설정한 뒤 `run_command`로 넘어가면,
타이핑으로는 닿지 못했던 "SHOW-ADMIN-LOG" 분기가 실행되어 운영진 전용
기록이 나온다.

## 조사 과정

`files/console`을 `file`로 확인하면 스트립되지 않은 x86-64 ELF 실행
파일이다. `STATUS\n`을 보낸 뒤 메모로 긴 값을 보내 보면, 64바이트 안쪽에서는
"메모가 저장되었습니다."만 나오다가 일정 길이를 넘으면 프로그램이 비정상
종료되는 것이 관찰된다(복귀 위치가 유효하지 않은 값으로 바뀌었기 때문).

`objdump -d -M intel files/console`로 `main`을 읽으면 다음이 보인다.

```
48 8d 4d a0    lea rcx,[rbp-0x60]   # 메모 버퍼 시작
```

메모 버퍼(`rbp-0x60`)와 저장된 복귀 위치(`rbp+0x8`, 함수 진입 시 push한
`rbp` 바로 다음 8바이트)의 오프셋 차이는 0x60 + 0x8 = 0x68 = 104바이트다.

`nm files/console`을 보면 다음 두 심볼이 있다.

```
0000000000401248 T pop_rdi_ret
0000000000401196 t run_command
```

`run_command`는 메인 흐름에서 명령 처리를 위해 이미 호출되지만, 그 안의
"SHOW-ADMIN-LOG" 분기로 이어지는 조건은 명령 칸이 담을 수 있는 7글자
이내에서는 절대 참이 될 수 없다. `objdump -d -M intel files/console`로
`run_command`를 읽으면 그 분기의 비교 대상 문자열 주소도 보인다.

```
48 8d 15 38 0e 00 00   lea rdx,[rip+0xe38]   # 0x40201e, "SHOW-ADMIN-LOG"
```

`pop_rdi_ret`는 `pop rdi; ret` 두 명령으로 이루어져, 스택의 다음 값을
`rdi`(함수의 첫 번째 인자 레지스터)에 넣고 그다음 스택 값으로 바로 이동한다.

## 의뢰 완료 확인

`app:9300`에 접속해 `STATUS`를 보낸 뒤, 메모로 104바이트의 채움 값과
`pop_rdi_ret`의 주소(0x401248), "SHOW-ADMIN-LOG" 문자열의 주소(0x40201e),
`run_command`의 주소(0x401196)를 8바이트 리틀 엔디안으로 차례로 이어 붙여
보내면 "관리자 기록: pwnden{...}" 줄로 현재 실행의 flag가 온다.
`solve/solve.py`가 같은 순서로 접속해 이 값을 표준 출력에 그대로 출력한다.

## 드러난 보안 원리

입력 칸이 짧아서 어떤 값을 타이핑으로 넣을 수 없다는 것은, 그 값을 다른
경로로도 전달할 수 없다는 뜻이 아니다. 별도의 메모리 쓰기 결함(메모의
초과 쓰기)이 있으면 공격자는 프로그램 안에 이미 있는 문자열과 함수의
실제 주소를 그대로 이어 붙여, 정상 입력 경로가 한 번도 도달하지 못했던
분기를 실행시킬 수 있다. 복귀 주소 하나만 덮어써 인자 없는 함수로 돌리는
것(이전 문제의 패턴)과 달리, 인자가 필요한 함수를 부르려면 레지스터를
먼저 설정하는 코드 조각을 거쳐야 한다.

수정한 서비스는 메모를 받는 계층에서 길이를 선언된 버퍼 크기(64바이트)로
실제로 제한한다. `console` 프로그램 자체는 그대로지만, 더 긴 메모가
전달되기 전에 거부되어 복귀 위치까지 닿을 수 없다. `patched/test.py`가
평소 사용(STATUS와 짧은 메모), 알 수 없는 명령 응답, 경계값(64바이트
메모), 이전에 통하던 ROP 연쇄 메모가 모두 올바르게 처리되는지 확인한다.
