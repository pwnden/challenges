::message{from="흐린응답"}
없는 주소도 전부 정상이라고 나와요. 상태 코드만 보면 구분이 안 됩니다. 운영 자료가 공개돼 있다는 제보를 실제 본문으로 확인해 주세요.
::

:person[흐린응답]은 납품 보드의 운영 담당자다. 보드는 공개 도움말과 서비스 상태를
누구나 읽게 한다. 운영 점검 자료와 장애 복구 코드는 담당자만 읽어야 한다.

서버는 없는 주소를 요청해도 공통 안내 페이지와 상태 코드 200을 돌려준다.
운영 자료를 읽을 수 있다는 제보가 왔지만, 상태 코드만 보면 실제 자료를 받은 것인지
안내 페이지를 받은 것인지 알 수 없다. 흐린응답은 실습 서버 주소와 작은 후보 목록,
자료 공개 규칙을 길드에 전달하고 실제로 비공개 자료를 읽을 수 있는지 확인을 맡겼다.

::objective
공통 안내와 다른 응답을 찾고, 실제 본문을 공개 정책과 비교해 잘못 공개된 복구 코드를 확인하자.
::

::resources{title="서버와 후보 자료"}
- 서버 주소는 문제 네트워크의 `http://app:8000`이다.
- `files/paths.txt`에는 조사할 후보 경로 12개가 있다.
- `files/public-policy.txt`는 공개 가능한 자료의 범위를 정한다.
- `/help`와 `/healthz`는 공개 기능이다.

먼저 서로 다른 없는 주소의 본문을 저장하고 비교하자.

```sh
curl -sS http://app:8000/does-not-exist -o first.json -w '%{http_code}\n'
curl -sS http://app:8000/another-missing -o second.json -w '%{http_code}\n'
wc -c first.json second.json
cmp first.json second.json
```

이 서버는 여러 JSON 응답의 길이를 같은 크기로 맞춘다. 크기가 같아도 내용은
다를 수 있다. 두 안내의 JSON을 읽고 공통 안내임을 나타내는 view 값을 확인하자.
아래 예제는 해당 표시를 가진 응답만 제외한다. 남은 주소를 curl과 jq로 읽어
실제 내용과 공개 정책을 비교하자.

```sh
ffuf -w files/paths.txt -u http://app:8000/FUZZ -fr '"view":"fallback"' -t 2 -rate 10 -maxtime 15
```

### 준비된 터미널 명령 사용하기

터미널에는 한 줄의 명령을 입력하고 Enter를 누르면 된다. `files/`로 시작하는
경로는 이 문제의 배포 파일을 가리킨다. 명령 예제의 파일명은 조사할 자료의 이름으로 바꿔 넣자.

`printf '%s' 'hello'`는 줄바꿈 없이 `hello`를 출력한다.
`|`는 왼쪽 출력물을 오른쪽 프로그램의 입력으로 전달한다.
예를 들어 `printf '%s' 'hello' | sha256sum`은 정확히 다섯 글자를 해시한다.
`hello` 뒤에 줄바꿈이 추가되면 해시도 달라진다.

각 문제의 ‘전달받은 자료’에서 파일을 읽고 결과를 확인할 명령을 안내한다.
Ctrl+C는 오래 실행되는 명령을 중단하고, 위쪽 화살표는 이전 명령을 다시 가져온다.

### Web 요청과 응답 읽기

사이트에서 버튼을 누르거나 주소를 열면 브라우저는 서버에 **요청**을 보내고,
서버는 상태와 내용을 담은 **응답**을 돌려준다. `GET`은 자료 조회에 흔히 쓰이는 요청 방식이다.

예를 들어 `GET /help`는 도움말을 요청한다. 응답의 `200`은 요청 성공,
`403`은 접근 거절, `404`는 찾을 수 없는 자료를 뜻한다. 화면에 오류 안내가 뜨면
입력한 값과 응답 내용을 함께 살펴보자. 상태 번호만으로 자료의 내용까지 알 수는 없다.

**헤더**는 쿠키나 내용 형식 같은 부가 정보다. **본문**은 페이지, 문서, 데이터 자체다.
같은 주소라도 요청에 실린 정보에 따라 서버가 다른 내용을 돌려줄 수 있다.

### 응답을 비교해 후보 줄이기

없는 주소가 안내 페이지로 연결되면 상태 코드가 200이어도 자료가 있다는 뜻은
아니다. `curl -sS 주소 -o body.json -w '%{http_code}\n'`은 본문을 파일에 저장하고
상태 코드를 출력한다. `wc -c < body.json`은 본문의 바이트 수를 센다.

같은 대상의 서로 다른 없는 주소가 동일한 안내를 주는지 먼저 비교한다.
`cmp first.json second.json`은 두 파일이 같으면 아무것도 출력하지 않고 끝난다.

`ffuf -w 후보파일 -u http://대상/FUZZ -fs 크기 -t 2 -rate 10 -maxtime 15`는
파일의 각 줄을 FUZZ 자리에 넣어 요청한다. `-fs`는 지정한 본문 크기를 제외한다.
`-t`는 동시에 요청할 작업 수, `-rate`는 초당 요청 수, `-maxtime`은 전체 시간
상한이다. 크기가 다른 응답은 조사할 후보이며 내용은 직접 확인해야 한다.

본문 길이가 같아도 내용은 다를 수 있다. 크기 필터가 필요한 응답도 숨긴다면
공통 안내에만 있는 표시를 확인한다. `-fr '"view":"fallback"'`은 이 문자열을
가진 응답을 제외한다. -fr은 정규식 필터이므로 모든 JSON을 제외하는 넓은
조건 대신 안내의 구체적인 표시를 고른다. cmp와 jq로 본문을 비교해 판단한다.

예를 들어 공개 도움말도 안내 페이지와 크기가 다르다. 후보가 나왔다고
비공개 자료가 유출됐다고 단정하지 말고, `curl`로 실제 본문을 읽어 공개 정책과
비교한다. `jq .`는 JSON을 읽기 좋게 표시한다.
