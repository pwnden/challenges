## 조사 결과

`CHECK`는 메모를 봉인할 때 쓴 것과 같은 무작위 값(패드)을 그대로 다시
사용했다. 같은 길이의 0으로만 이루어진 값을 `CHECK`에 보내면 그 응답이
곧 패드 자체가 되고, 그 패드를 `MEMO`의 응답과 XOR하면 메모의 원문이
그대로 나왔다.

## 조사 과정

`ncat -w 3 --idle-timeout 1 app 9200`으로 접속하면 `MEMO-VAULT/1` 배너가
먼저 온다. `MEMO`를 보내면 현재 메모를 봉인한 16진수 값을 돌려준다.

같은 값을 `CHECK`에 두 번 보내면 매번 같은 응답이 온다. 매번 새 패드를
쓴다면 이럴 수 없으므로, `CHECK`가 고정된 패드를 계속 쓴다는 뜻이다.

`MEMO`의 응답 길이만큼(바이트 수 기준) 0만 담은 값을 `CHECK`에 보내면,
XOR에서 0과의 연산이 원래 값을 그대로 남기므로 그 응답이 곧 패드 자체가
된다. 이 패드를 `MEMO`의 응답과 다시 XOR하면 원문이 복원된다. 두 값이
같은 패드에서 나왔다는 사실은 "같은 입력을 `CHECK`에 반복해도 항상 같은
응답이 온다"는 관찰로 뒷받침된다.

## 의뢰 완료 확인

`solve/solve.py`는 `MEMO`로 봉인 값을 받고, 같은 길이의 0 값을 `CHECK`에
보내 패드를 얻은 뒤, 둘을 XOR해 원문을 그대로 출력한다.

## 드러난 보안 원리

평문과 같은 길이의 무작위 값을 한 번씩만 XOR하는 방식(일회용 패드)은 그
값을 정말 한 번만 쓸 때만 안전하다. 같은 패드를 다른 평문에도 다시 쓰면,
공격자가 그 평문 하나를 알거나 직접 고를 수 있는 경우 패드 자체를 계산해
낼 수 있고, 그 패드로 다른 암호문도 복호화할 수 있다.

패치한 서버는 `CHECK`를 처리할 때마다 메모의 패드와 무관한 새 무작위
값을 생성한다. `patched/test.sh`는 같은 입력을 `CHECK`에 반복해도 응답이
매번 달라진다는 것과, 더 이상 그 응답으로 메모 원문을 복원할 수 없다는
것을 확인한다. `HELLO`·`MEMO`의 기본 동작과 오류 응답은 패치 전후로 그대로
유지된다.
