::message{from="봉인지기"}
작은 메모 보관소를 운영하고 있어요. 메모 하나하나를 무작위 값으로 한 번씩
봉인(XOR)해서 저장한다고 알고 있는데, 점검용으로 만든 CHECK 기능이 그
봉인과 같은 값을 쓰는 건 아닌지 확신이 안 서요. CHECK는 제가 보낸 값을
그대로 봉인해서 보여 주는 기능이에요. 대상 호스트와 명령 몇 개를 드릴
테니, CHECK가 메모와 같은 값을 재사용하는지 확인해 주세요.
::

:person[봉인지기]는 작은 메모 보관소를 관리한다. 보관소는 메모 하나를
저장하며, 그 메모는 무작위 값으로 한 번씩 XOR해 봉인한 형태로만 꺼내 볼 수
있다. 운영 중에는 점검용으로 임의의 값을 같은 방식으로 봉인해 보여 주는
CHECK 기능도 켜 두었다.

봉인지기는 CHECK가 매번 새 무작위 값을 쓰는지, 아니면 메모를 봉인한 값과
같은 값을 다시 쓰는지 직접 확인해 보지 못했다. 조사 대상은 CHECK로 봉인한
결과와 메모의 봉인 결과가 같은 값에서 나왔는지이며, 확인된다면 메모의
원문(flag)을 복원하는 것까지가 의뢰 범위다.

::objective
CHECK 점검 기능이 메모를 봉인한 값과 같은 값을 재사용하는지 확인하고,
현재 메모의 원문을 알아내자.
::

::resources

- 대상 호스트: 문제 네트워크 안의 `app`, 포트 9200.
- 프로토콜: 줄바꿈으로 끝나는 텍스트 명령. `HELLO`, `MEMO`, `CHECK <16진수>`.
- `MEMO`는 현재 메모를 봉인한 값을 16진수 문자열로 돌려준다.
- `CHECK <16진수>`는 보낸 값을 같은 방식으로 봉인해 16진수로 돌려준다.
  입력은 1~128바이트(16진수 문자 2~256자)로 제한된다.
::

::submission
복원한 메모 원문의 `pwnden{...}` 값을 제출하자. 실행 환경을 새로 준비하면
값이 바뀐다.
::
