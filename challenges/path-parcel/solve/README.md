## 조사 순서

1. `welcome.txt`가 정상적으로 읽히는지 확인한다.
2. `guide.txt`에서 public과 private가 같은 상위 폴더에 있으며 운영 파일명이 recovery.txt임을 읽는다.
3. 현재 출발 폴더가 public이므로 `../`로 상위 폴더를 가리킨다.
4. 파일명 입력칸에 `../private/recovery.txt`를 넣는다.
5. 운영 복구 기록에 표시된 `pwnden{...}`를 제출한다.

`./../private/recovery.txt`도 같은 위치를 가리킨다.

## 확인된 원리

대상은 실제 파일을 읽는다. 입력을 공개 폴더와 이어 붙여도 `..`의 의미가 사라지지 않아,
최종 위치는 공개 폴더 밖이 된다. 폴더 분리와 접근 제한은 각각 구현해야 한다.

## 고친 동작

수정한 서버는 `.`과 `..`를 계산해 실제 파일 위치를 찾은 뒤 공개 폴더 안에 있는지 확인한다.
위 경로와 절대 경로 입력은 `403`으로 거절하면서 welcome.txt와 guide.txt는 계속 읽힌다.
폴더 이름의 앞부분만 비교하면 public-other도 public으로 잘못 판단할 수 있다.
파일이 실제로 public 폴더 안에 있는지 확인해야 한다.

다른 응답을 만났다면 입력의 폴더 순서와 파일명을 다시 확인하자.
존재하지 않는 파일은 `404`, 비어 있는 입력은 `400`으로 처리된다.
