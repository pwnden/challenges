## 조사 결과

이름을 받는 `fgets` 호출이 선언된 배열 크기(64바이트)보다 4배 큰
256바이트까지 받아들인다. 배열 바로 다음에 저장된 `is_staff` 값까지 이름
입력으로 덮어쓸 수 있고, 77바이트를 채운 뒤 줄바꿈 한 글자만 보내면
`is_staff`가 0이 아닌 값으로 남아 직원 전용 자료가 나온다.

## 조사 과정

`files/vault`를 `file`로 확인하면 스트립되지 않은 x86-64 ELF 실행 파일이다.
`objdump -d -M intel files/vault`로 `main`을 읽으면 다음이 보인다.

```
c7 45 fc 00 00 00 00    mov DWORD PTR [rbp-0x4],0x0      # is_staff = 0
48 8d 45 b0             lea rax,[rbp-0x50]               # name의 시작 주소
be 00 01 00 00          mov esi,0x100                    # fgets에 넘기는 크기 = 256
e8 .. ..                call fgets@plt
```

`name`은 `rbp-0x50`(스택 포인터 기준 80바이트 지점)에서 시작하고
`is_staff`는 `rbp-0x4`에 있다. 두 오프셋의 차이는 80 − 4 = 76바이트다.
그런데 `fgets`에 넘기는 크기는 64가 아니라 256(0x100)이다. 소스의
`fgets(name, sizeof(name) * 4, stdin)`가 선언한 배열 크기의 4배를 그대로
넘겨서, 76바이트를 넘는 입력은 `is_staff`의 메모리까지 이어서 쓴다.

실제 접속에서 길이를 하나씩 늘려 가며 확인하면 경계는 76바이트가 아니라
77바이트다. `A` 76개 뒤에 줄바꿈만 보내면(총 77바이트) 줄바꿈 글자가
`is_staff`의 첫 바이트에 들어가 잠시 0이 아닌 값이 되지만, 그 직후
`name[strcspn(name, "\n")] = '\0';`가 방금 찾은 그 줄바꿈 위치에 다시 NUL을
써서 같은 바이트를 0으로 되돌린다. `A` 77개 뒤에 줄바꿈을 보내면(총 78바이트)
`is_staff`의 첫 바이트에는 `A`(0x41)가 남고, NUL 재작성은 그다음 바이트
(`is_staff`의 두 번째 바이트)에서 일어나 첫 바이트의 값을 건드리지 않는다.
그래서 77바이트 이하는 "손님 접근만 허용됩니다."로 남고, 78바이트부터
"직원 전용 자료"로 바뀐다. 오프셋을 디스어셈블리만으로 계산해도 끝이 아니라,
그 뒤에 나오는 트림 코드까지 같은 메모리를 다시 건드리는지 확인해야 정확한
경계를 알 수 있다는 뜻이다.

## 의뢰 완료 확인

`app:9100`에 접속해 `A`를 77개 보낸 뒤 줄바꿈 하나를 보내면(총 78바이트)
"직원 전용 자료: pwnden{...}" 줄로 현재 실행의 flag가 온다.
`solve/solve.py`가 같은 길이의 입력으로 접속해 이 값을 표준 출력에 그대로
출력한다.

## 드러난 보안 원리

지역 변수는 스택이라는 하나의 메모리 구간에 나란히 놓인다. 배열에 쓰는
코드가 배열의 실제 선언 크기보다 더 긴 입력을 그대로 받아들이면, 넘친 값이
바로 옆 변수의 메모리를 덮어써서 그 변수가 지키려던 조건을 입력만으로
우회할 수 있다. 변수의 선언 순서와 실제 메모리 배치, 그리고 코드가 실제로
받아들이는 길이는 디스어셈블리로 확인해야 하는 사실이지 소스의 변수 크기
선언만으로 보장되지 않는다.

실제 원인은 `vault` 프로그램의 `fgets` 호출이 선언된 배열 크기의 4배를
그대로 받아들이는 것이다. 수정한 서비스는 그 호출 자체는 그대로 두고, 연결을
받는 계층에서 이름 한 줄의 길이를 배열의 실제 크기(64바이트)와 줄바꿈을 더한
65바이트로 제한해 더 긴 줄은 `vault` 프로그램에 전달하기 전에 거부한다.
`patched/test.py`가 평소 길이의 이름과 경계값(63바이트)은 그대로 통과하고,
이전에 통하던 77개의 `A`와 줄바꿈, 훨씬 더 긴 200바이트 입력은
`ERR name_too_long`으로 거부되어 flag가 나오지 않음을 확인한다.
