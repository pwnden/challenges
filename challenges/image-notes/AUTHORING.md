# 공개 이미지에 남은 내부 메모 작성 기록

## 현재 설명 구성 (2026-10-04)

기본 브리핑에는 상황·목표·범위·접근 정보·자료 위치·제출 대상을 둔다.
풀이자는 자료를 읽고 사용할 도구와 비교 기준을 선택한다. 선택형 힌트가 막힌
판단을 돕고, 해설이 재현 명령과 결론을 설명한다. 공통 개념은 학습 연결에서
필요할 때 읽는다. 명령 예제를 기본 본문에 제공했던 기존 설계의 시작 정보·판단·
힌트 평가는 재검토 대기이며, 새 본문에 대한 심사를 완료했다고 간주하지 않는다.

이하 검토·설계 기록은 작성 당시 버전의 근거다. 본문의 명령 예제나 조작 설명을
언급하는 과거 기록은 현재 기본 브리핑의 제공 정보로 사용하지 않는다.

## 설정과 목표

모래시계는 작업 보드 담당자다. 공개할 배너를 내보낸 뒤 내부 속성도 포함됐다는
제보를 받아 독립 확인을 의뢰한다. 배포 규칙·그림·Description·Comment가 실제 자료다.
보드 복구 코드는 교육용 값이며 실제 계정과 연결되지 않는다.

- 분야: `digital-forensics`, 주제: `forensics-files-metadata`, category: `forensics`.
- teaches: 픽셀과 속성을 구분하고 파일의 실제 공개 범위를 확인한다.
- 대상: 준비된 명령을 입력하고 JSON 항목을 비교할 수 있는 초급자.
- requires `terminal-commands`, `image-metadata`: 공통 문서를 기본 브리핑에 포함한다.
- 일반 풀이에는 Python 작성과 이미지 편집이 필요하지 않다.

## 의도된 관찰과 난도

1. 배포 규칙은 운영 메모를 공개 범위에서 제외한다.
2. ExifTool에서 내보낸 배너 기록과 여러 메모를 발견한다.
3. ID·버전·활성 상태를 맞춰 이번 배너의 코드를 선택한다.

난도 2 초급을 제안한다. 명령과 작은 필터 예제를 제공하되 서로 다른 속성을
연결해 선택해야 한다. 다른 배너의 활성 기록과 같은 배너의 교체 전 기록이
자연스러운 오답이다. jq 없이 두 JSON을 직접 비교하는 경로도 유효하다.

## 자료 생성과 검증

`python3 authoring/build.py`는 stdlib로 PNG·내보내기 기록·메모 목록을 재생성한다.
`authoring/check.py`는 실제 file·ExifTool 파싱, 원본과 재생성 바이트의 일치,
속성 제거 후 픽셀 동일성·코드 회수 실패와 다른 배너/교체 코드의 제출 해시 불일치를 검사한다.
풀이·대조 검사는 `pwnden-cli:basic-20261003`에서 수행한다.

작성자 기록과 자동 풀이에는 정답이 있다. 웹의 기본 본문과 파일 탭에는 선언한
자료만 노출한다. 로컬 카탈로그는 비밀 저장소로 취급하지 않는다.
