::message{from="모래시계"}
작업 보드에서 배너를 내보냈는데, 그림에는 없는 내부 메모도 같이 나갔다는 제보가 왔어요. 공개 파일에 무엇이 들어 있는지 확인해 주세요.
::

모래시계는 작은 팀의 작업 보드를 관리한다. 보드의 파란색 배너는 외부 안내에
사용해도 되지만, 보드 복구 코드와 운영 메모는 팀 안에서만 보관해야 한다.
복구 코드는 보드 관리 기능을 되찾을 때 사용하는 비밀값이다.

그림을 내보내는 도구가 보드의 속성까지 파일에 넣었을 가능성이 있다.
모래시계는 공개한 파일과 배포 규칙을 전달하고, 화면에 보이지 않는 정보도
외부에 전달됐는지 재확인해 달라고 의뢰했다. 자료는 이 실습을 위해 만든 PNG다.

::objective
공개 이미지의 실제 형식과 속성을 조사하고, 함께 저장된 내부 복구 코드를 찾자.
::

::resources{title="공개한 파일과 배포 규칙"}
- `files/notice.png`: 파란 테두리와 밝은 중앙 영역을 가진 배너 파일.
- `files/export-policy.txt`: 공개해도 되는 정보의 범위.

터미널에 파일 조사 도구가 준비돼 있다. 먼저 규칙과 파일 형식을 확인하자.

```sh
cat files/export-policy.txt
file files/notice.png
exiftool files/notice.png
```

속성에 JSON 형태의 메모가 보이면 아래 설명의 작은 예제를 참고해 내용을 읽자.
::

::knowledge

### 준비된 터미널 명령 사용하기

터미널에는 한 줄의 명령을 입력하고 Enter를 누르면 된다. `files/`로 시작하는
경로는 이 문제의 배포 파일을 가리킨다. 명령 예제의 파일명은 조사할 자료의 이름으로 바꿔 넣자.

`printf '%s' 'hello'`는 줄바꿈 없이 `hello`를 출력한다.
`|`는 왼쪽 출력물을 오른쪽 프로그램의 입력으로 전달한다.
예를 들어 `printf '%s' 'hello' | sha256sum`은 정확히 다섯 글자를 해시한다.
`hello` 뒤에 줄바꿈이 추가되면 해시도 달라진다.

파일을 읽는 명령과 결과를 확인하는 명령은 문제의 전달받은 자료에 제공한다.
Ctrl+C는 오래 실행되는 명령을 중단하고, 위쪽 화살표는 이전 명령을 다시 가져온다.

### 이미지와 메타데이터

이미지 파일에는 그림을 나타내는 데이터 외에 제목·설명·작성 도구 같은 속성이
들어갈 수 있다. 이 속성을 메타데이터라고 한다. 화면에 보이는 그림만 검토하면
파일에 함께 저장된 속성을 놓칠 수 있다.

`file 경로`는 실제 파일 형식을 확인한다. `exiftool 경로`는 이미지의 속성을
이름과 값으로 보여 준다. 특정 속성의 값만 읽으려면 `exiftool -s3 -속성이름 경로`를
사용한다. 출력에는 파일이 기록한 정보가 포함되며, 그 정보가 사실인지는 다른
자료와 비교해야 한다.

속성 값이 JSON이라면 `jq`로 필드를 선택할 수 있다. JSON의 객체는 이름과 값으로
구성된다. 예를 들어 `printf '%s' '{"memo":{"status":"draft"}}' | jq -r '.memo.status'`는
`draft`를 출력한다. 점은 객체 안으로 들어가는 경로이며 `-r`는 따옴표를 제거한다.

파이프 `|`는 앞 명령의 출력을 다음 명령의 입력으로 전달한다. 그림의 픽셀을
바꾸지 않고 메타데이터만 제거할 수도 있으므로, 공개할 때는 두 범위를 함께 확인한다.
::
