# 시나리오 작성 기록

이 기록은 2026-10-13에 문제 파일과 `quality/` 기록을 읽고 처음 작성했다. 문제를 만들 때 남긴
작성 기록은 없었으므로 설계 의도를 당시 작성자에게 확인한 내용이 아니다.

## 시나리오 설정

- 표시 제목: 잠금장치의 입력 검사
- 한 줄 소개: 오래된 보관함을 인수한 관리자가 비밀번호를 잃어버려 길드에 검사 코드 분석을 맡긴다.
- 공개 닉네임과 말투: 정해진 닉네임이 없다. 브리핑은 관리자를 직책으로만 부르고 서술체로 쓴다. README에 의뢰 `message` 블록이 없다.
- 의뢰인과 플레이어의 역할: 관리자가 검사 코드 `files/checker.py`를 전달하고 플레이어는 이를 분석한다.
- 대상과 사건의 계기: 장치는 정상 작동하지만 이전 비밀번호가 남아 있지 않다.
- 길드를 찾은 이유: 코드는 있으나 비밀번호는 코드에 없어서 분석을 맡겼다는 설정이다.
- 이번에 공개할 정보: 검사기가 입력을 바이트 숫자로 바꿔 연산하고 저장된 숫자 목록과 비교한다는 것, 입력을 바꾸는 방법과 최종 비교값이 코드에 있다는 것, `unlocked`와 `locked` 출력.
- 의뢰 목표와 완료 증거: 검사기가 `unlocked`를 출력하는 입력 문자열 전체 `pwnden{...}`를 제출한다.
- 처음 전달할 사실: 위 공개 정보와 제출 형식.
- 사건의 흐름: 비밀번호 분실 → 검사 코드 확보 → 코드를 읽고 입력을 복원하도록 분석 의뢰.
- 조사 중 발견할 사실: 각 바이트가 마스크와 이전 출력으로 섞인 뒤 회전되며, 이를 거꾸로 하면 입력이 나온다.
- 풀이자에게 남긴 판단: 코드를 읽고 어떤 연산을 어떤 순서로 되돌릴지, 직접 계산할 도구를 정할지를 풀이자가 정한다. 힌트 둘이 점진적으로 범위를 좁힌다.
- 학습 목표와의 연결: 입력 검사 코드가 변형과 비교값을 모두 공개하면 입력을 되돌릴 수 있음을 직접 확인한다.

## 학습 목표와 대상

- 현재 계약의 category: rev
- 학습 분야: 이 기록에 별도 분야가 없다. `docs/learning-order.md`는 이 문제를 코드 분석 독립 분기로 둔다.
- 세부 주제: 위와 같다.
- category 선택 근거: 코드를 읽고 입력을 복원하는 문제라 rev다.
- 보안 학습 목표: 변형과 최종 비교값을 모두 아는 입력 검사는 거꾸로 계산해 입력을 복원할 수 있음을 입증한다.
- 확인할 보안 원리: XOR와 회전은 값을 숨길 수 있지만 변환 방식과 결과를 공개하면 비밀번호를 보호하지 못한다.
- 대상 풀이자: 터미널과 파일 경로, 짧은 코드의 반복·조건·비트 연산을 읽을 수 있는 입문자. 난도 2.
- 시작 조건과 성공 증거: `files/checker.py`와 터미널(`python3`)이 주어진다. 검사기의 `unlocked`와 제출한 플래그가 성공 증거다.

## 의도된 풀이

| 단계 | 풀이자가 수행할 행동 | 발견·관찰할 내용 | 필요한 지식·도구 |
| --- | --- | --- | --- |
| 1 | `checker.py`의 `encode`를 읽는다. | 마스크 XOR, 이전 출력 XOR, 위치별 회전이다. | 코드 읽기 |
| 2 | 각 연산을 반대로 적용한다. | `TARGET`에서 입력 바이트가 나온다. | 비트 연산 |
| 3 | 복원한 문자열을 검사기에 넣는다. | `unlocked`가 출력된다. | 터미널, `python3` |

보안 학습 목표와의 연결: 2단계가 공개된 변형이 보호가 되지 못한다는 점을 보여 준다.

풀이자의 언어 지식: 짧은 Python 코드를 읽고 몇 줄의 계산 코드를 쓸 수 있어야 한다. 해설이 풀이 코드를 제공하므로 코드 작성이 필수는 아니다.

## 개념 관계

- 문제의 선수 개념: `terminal-commands`, `file-paths`, `program-reading`.
- 문제의 학습 개념: `input-checks`.
- 개념 간 선수 관계: `input-checks`는 `program-reading`을 요구한다. 순환이 없음은 검증 도구가 확인한다.
- 관련 읽기: `encoding-secrecy`, `query-boundaries`. 카탈로그가 `input-checks`의 관련 개념으로 지정한다.
- 공개 위치: 선수 개념은 시작 전, 학습 개념은 풀이 후 확인한다.

## 난도 근거

- 선언한 값: 2 (1 입문, 2 초급, 3 중급, 4 고급, 5 심화)
- 선수 지식 부담: 코드의 반복·조건·비트 연산 읽기. `docs/learning-order.md`는 앞의 CLI 문제를 푼 것만으로 이 능력을 갖췄다고 보지 않는다고 적는다.
- 발견 난도: 코드가 모두 주어져 있고 되돌릴 연산을 찾는 일이 핵심이다.
- 구현 부담: 해설의 짧은 계산 코드를 실행하거나 직접 쓴다.
- 풀이 의존성: 연산 순서와 `previous` 값의 의미를 모두 맞아야 한다. 힌트가 `previous`가 앞선 출력임을 알려 준다.
- 등급 판정: 별도 기록이 없다. 초급으로 선언되어 있다.

manifest의 difficulty를 바꾸면 이 기록도 함께 갱신하세요.

## 다른 풀이와 정답 노출

- 확인한 다른 풀이: 기록이 없다.
- 의도치 않은 지름길 점검: 검사기는 후보를 넣고 `unlocked`와 `locked`만 알려 준다. 정답 해시는 manifest에 있고 파일 모드는 `sha256`이다.
- 본문 노출 점검: 본문은 변형 방식을 서술하지만 연산의 종류와 순서는 적지 않는다. 힌트 1이 마지막 연산이 회전임을 알려 준다.
- 필요한 힌트: 2개.
- 해설: 변형을 정리하고 역변환한 뒤 코드로 복원한다.
