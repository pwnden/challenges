팀 문서 사이트는 문서를 수정할 때 이전 내용을 변경 기록에 보관한다.
팀원은 공유 작업 노트의 현재 내용과 변경 기록을 모두 읽을 수 있다.
:person[잔비]는 운영자의 복구 문서에 팀원의 읽기를 거절하는 규칙을 추가했다.
이 문서에는 장비에 다시 접근할 때 필요한 비밀값인 복구 키가 기록된 적이 있다.

잔비가 확인한 것은 현재 문서를 직접 열었을 때 거절된다는 사실이다.
네게는 팀원 계정과 현재 적용 중인 권한 규칙이 주어졌다.
공유 노트에서 사이트의 읽기 기능을 살펴보고, 운영자의 자료가 같은 경계 안에서
보호되는지 조사하자.

공유 노트의 현재 문서와 변경 기록 링크로 기능을 확인할 수 있다.

웹 도구의 주소창에서 페이지 경로와 요청 값을 살펴보거나 바꿀 수 있다.

### 누가 어떤 문서를 읽을 수 있나

접근 권한은 누가 어떤 자료를 읽거나 바꿀 수 있는지 정한다.
이 권한을 판단하는 규칙을 **권한 정책**이라고 한다. 이번 사이트는 팀원이 요청한
문서 이름을 규칙과 비교해, 내용을 보여 줄지 거절할지 결정한다.

사이트에 보이는 규칙은 다음 항목으로 읽는다.

- `Effect`: `Allow`는 허용, `Deny`는 거절이다.
- `Action`: 허용하거나 거절할 동작이다. 현재 문서 읽기와 기록에 저장된 문서 읽기는 서로 다른 동작일 수 있다.
- `Resource`: 규칙을 적용할 자료의 이름이다. 이 문제에서는 문서 이름을 가리킨다.

예를 들어 `Action: "read"`, `Resource: "box/guest-*"`는 이름이
`box/guest-`로 시작하는 문서를 읽도록 허용한다. `*`는 뒤에 오는 글자 전체를 대신한다.
`box/guest-note`와 `box/guest-backup`은 둘 다 해당한다.
동작 이름에도 같은 규칙을 적용한다. `view*`는 `view`, `view-list`처럼
`view`로 시작하는 동작에 모두 맞고, `view`는 그 이름의 동작 하나에만 맞는다.

이번 사이트는 대소문자를 구분한다. 일치하는 허용 규칙이 없으면 거절하며,
일치하는 `Deny` 규칙이 있으면 허용 규칙이 있어도 거절한다.
이 설명은 제공된 사이트에서 사용하는 규칙을 다룬다.
