## 조사 순서

1. `locker/team-notes`를 읽어 팀 공유 자료가 정상적으로 열리는지 확인한다.
2. 현재 정책의 동작이 read이며 리소스 패턴이 `locker/team-*`인 것을 읽는다.
3. 목록의 `locker/team-admin`도 team- 뒤에 글자가 붙는 이름이므로 패턴에 들어간다.
4. 이 전체 이름으로 읽기 요청을 보낸다.
5. 응답에 나타난 운영 복구 키 `pwnden{...}`를 제출한다.

개인 초안인 `locker/personal-draft`는 같은 정책에 맞지 않아 거절된다.
정상 요청과 거절 요청을 함께 비교하면 허용 규칙의 범위를 설명할 수 있다.

## 확인된 원리

team-reader라는 역할 이름과 '운영자 전용' 표시만으로 접근 결과가 정해지지는 않는다.
평가기의 실제 정책은 동작과 리소스 이름을 비교한다.
광범위한 wildcard가 이름이 비슷한 별도의 보관소까지 포함한다.

## 고친 동작

패치는 허용 리소스를 `locker/team-notes`로 좁힌다.
공유 노트는 계속 읽히며 운영 보관소와 비슷한 접미사가 붙은 이름은 거절된다.
권한 검토에서는 정상적으로 필요한 작업과 의도하지 않은 대상 모두를 확인한다.

이 사이트는 명시된 정책 요소를 평가하는 로컬 학습 대상이다.
실제 클라우드의 권한은 공급자의 정책 종류와 조건, 다른 정책의 결합까지 확인해야 한다.
