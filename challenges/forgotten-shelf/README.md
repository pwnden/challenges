보관소를 옮기면서 백업을 만들었어요. 공개 목록도 정리했는데, 그 파일이 아직 열린다는 말을 들어서요. 한번 확인해 주실래요?
::

:person[잔비]는 문을 닫은 팬사이트와 개인 홈페이지의 흔적을 모으는 작은 웹 보관소를
돌보고 있다. 최근 보관소를 옮기면서 기존 자료를 백업 파일로 내보냈고,
작업이 끝난 뒤에는 방문자가 보는 목록에서 백업 파일로 가는 링크를 뺐다.
백업은 기존 자료를 다시 복원할 수 있도록 복사해 둔 파일이다.

그런데 누군가 여전히 백업 파일을 읽을 수 있다고 알려 왔다. 잔비는 목록을
둘러봐도 그 파일을 찾을 수 없어, 방문자가 어디로 들어가야 백업을 볼 수 있는지
길드에 확인을 맡겼다. 백업에는 사이트를 복구할 때 필요한 비밀값인 복구 키까지 들어 있다.
파일이 공개된 채 남아 있다면 그 비밀값도 함께 노출되는 상황이다.

네게 주어진 것은 일반 방문자가 접속하는 보관소와 이전 작업 때 사용한 파일 이름이다.
사이트에 남아 있는 안내를 살펴보고, 백업에 실제로 접근할 수 있는지 조사해 보자.

::objective

공개 웹사이트에서 백업을 찾아 읽고, 그 안의 복구 키를 제출하자.
::

::resources

- 웹 도구에서 보관소를 둘러볼 수 있다. 첫 화면의 ‘운영 안내’에는 이전 작업에 대한 정보가 있다.
- 이전 작업에서 만든 백업 파일의 이름은 `site-backup.txt`다.
- 사이트에는 검색 로봇을 위한 수집 안내가 남아 있다.
::

::knowledge

웹 도구의 주소창에서 `/about`처럼 경로를 입력하면 같은 사이트의 해당 페이지로 이동한다.
파일도 경로를 알면 같은 방법으로 열 수 있다.

`/robots.txt`는 검색 로봇에게 수집할 경로를 안내하는 공개 파일이다.
예를 들어 `Disallow: /drafts/`는 `/drafts/` 아래를 수집에서 제외해 달라는 뜻이다.
주소를 입력했을 때 실제로 읽을 수 있는지는 서버의 응답으로 확인해 보자.
::

::submission
복구 키는 `pwnden{...}` 형식이다. 실행 환경을 새로 준비하면 값이 바뀌므로,
현재 보관소에서 읽은 값을 제출하자.
::
