운영 담당자 :person[솔개로그]는 작업 보드 서버를 관리한다. 정식 HTTP 기능은 손님에게 보드
복구 정보를 제공하지 않는다. 복구 코드는 담당자가 장애 후 보드를 되살릴 때
사용하는 값으로, 연결 가능한 손님 누구나 읽을 수 있어서는 안 된다.

개발 중 사용한 점검 기능이 서버에 함께 남아 있다는 제보가 들어왔다.
솔개로그는 실습 서버와 좁은 포트 범위를 전달하고, 웹의 보호가 다른 기능에도
적용되는지 길드에 확인을 맡겼다. 점검 기능은 연결 후 도움말을 읽을 수 있는
줄 단위 텍스트 프로토콜을 사용한다.
추가로 열린 기능이 모두 민감한 자료를 제공하는 것은 아니다. 도움말로 역할을
구분하고 상태 응답이 가리키는 현재 자료를 확인하자. 폐기된 자료의 코드는 제출 대상이 아니다.

::resources{title="서버와 조사 범위"}
- 대상 호스트는 문제 네트워크 안의 `app`이다.
- 조사할 TCP 포트는 `8000-8010`의 11개다.
- 정식 HTTP는 `http://app:8000`, 복구 정보 요청은 `/api/recovery`다.
- 점검 프로토콜은 안내가 나온 뒤 한 줄의 명령을 받고 연결을 끝낸다.

먼저 웹 응답을 확인하고 제공된 범위의 포트 상태를 조사하자.

```sh
curl -i http://app:8000/api/recovery
nmap --unprivileged -sT -Pn -n -p 8000-8010 app
```

발견한 HTTP 이외의 포트에는 아래 예제의 번호를 실제 결과로 바꿔 도움말을 요청한다.

```sh
printf 'HELP\n' | ncat -w 3 --idle-timeout 1 app 발견한포트
```
