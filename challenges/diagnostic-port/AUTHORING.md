# 개발용 점검 포트 작성 기록

## 설정과 목표

솔개로그는 보드 서버 담당자다. 웹의 보호는 확인했으나 함께 남은 개발 기능에
대해 제보를 받아, 같은 실습 서버의 다른 포트를 재검증해 달라고 의뢰한다.

- 분야: `network-security`, 주제: `network-service-trust`, category: `misc`.
- teaches: 네트워크 연결 가능성과 민감한 자료를 읽을 권한을 구분한다.
- requires `terminal-commands`, `http-messages`, `tcp-services`: 포트·open/closed·
  TCP 연결·프로토콜 도움말·줄바꿈·대기 시간의 범위를 본문에 설명한다.
- 대상과 난도: 준비된 명령을 조정하는 초급자, 2 초급. 웹 거부·포트 발견·도움말·
  자료 읽기를 연결한다. 프로그램 작성과 raw 패킷 분석은 필요하지 않다.

## 실제 대상과 관찰

HTTP 8000과 TCP 8007을 컨테이너 하나에서 실행한다. 범위는 app의 11개 포트다.
HTTP는 복구 정보를 거부하지만 취약한 TCP는 인증 없이 `READ recovery`를 허용한다.
점검 기능은 한 줄을 받고 연결을 끝내며 불완전·긴 입력의 길이와 대기를 제한한다.
flag는 실행 시 주입하고 일반 상태와 HELP에는 넣지 않는다.

1. 정식 요청이 거부되는 것을 확인한다.
2. 비특권 Nmap TCP 연결 스캔으로 추가 listener를 발견한다.
3. Ncat으로 HELP·STATUS를 읽고 민감한 자료를 요청한다.
4. 수정 후에도 점검 기능은 열려 있지만 민감한 READ는 거부된다.

자동 해답은 스캔 결과의 열린 포트에서 점검 안내를 확인한다. 수정 서버에서
거부되면 계약상 코드 3을 반환한다. `patched/test.sh`는 열린/닫힌 포트,
HTTP의 거부·건강 검사, 정상 HELP·STATUS, 민감한 READ 거부와 잘못된 자료·
불완전 명령·알 수 없는 명령을 실제 연결로 검사한다. 직접 Ncat 대화도 유효하다.

Ncat 7.95의 socket EOF 이후 대기는 1초 idle 한도로 끝낸다. 자동 검사는
종료 코드 1을 해당 idle 메시지와 완전한 두 줄 응답이 함께 있을 때만 허용한다.
연결 실패와 불완전한 응답을 성공으로 처리하지 않는다.
