## 조사 결과

ECHO 기능은 화면에 "0-64바이트"라고 적어 두고도 실제로는 120바이트까지
그대로 돌려준다. 그 추가 구간에는 GREET 기능이 이름을 저장하는 자리 바로
뒤에 있는 보호값(스택 카나리)이 그대로 들어 있다. 이 값을 읽은 뒤 GREET에
같은 값을 되돌려주면 보호값 검사를 통과하고, 저장된 복귀 위치를 프로그램에
이미 있는 `grant_access` 함수의 주소로 덮어써 관리자 전용 출력을 끌어낸다.

## 조사 과정

`files/kiosk`를 `file`로 확인하면 스트립되지 않은 x86-64 ELF 실행 파일이다.
실제 접속에서 ECHO 요청 길이를 늘려 보면 64바이트를 넘어도 거부되지 않고
그대로 더 많은 바이트가 돌아온다. 같은 요청을 여러 번 반복하면 앞쪽 상당
구간은 매번 같은 값(초기화되지 않은 스택의 반복되는 내용)이지만, 104번째
바이트부터 8바이트는 요청할 때마다 달라진다. 이 구간의 첫 바이트는 항상
`0x00`이라는 점도 관찰된다 — 컴파일러가 넣는 보호값은 문자열 출력 함수가
그 값을 우연히 그대로 새어나가게 하는 사고를 줄이려고 마지막 바이트를
항상 0으로 둔다.

`objdump -d -M intel files/kiosk`로 `main`을 읽으면 다음이 보인다.

```
64 48 8b 04 25 28 00 00 00   mov rax,QWORD PTR fs:0x28   # 보호값 읽기
48 89 45 f8                  mov QWORD PTR [rbp-0x8],rax # 보호값 저장 위치: rbp-0x8
48 8d 45 80                  lea rax,[rbp-0x80]          # ECHO 버퍼 시작: rbp-0x80 (write 호출에 쓰임)
...
48 8d 4d b0                  lea rcx,[rbp-0x50]          # 이름 버퍼 시작: rbp-0x50
```

ECHO 버퍼(`rbp-0x80`, 코드에서 실제로 쓰는 시작 주소는 `rbp-0x70`으로
이어지는 `write` 호출에 쓰인다)와 보호값(`rbp-0x8`)의 오프셋 차이는
0x70 − 0x8 = 0x68 = 104바이트로, 실제 접속에서 찾은 "104번째 바이트부터
달라지는 8바이트"와 일치한다. 이름 버퍼(`rbp-0x50`)와 보호값의 오프셋
차이는 0x50 − 0x8 = 0x48 = 72바이트다. `nm files/kiosk`를 보면
`grant_access`라는 함수가 있는데, GREET 경로의 어떤 호출에서도 불리지
않는다.

## 의뢰 완료 확인

`app:9200`에 접속해 `120`을 보내 ECHO로 120바이트를 받으면 104~111번째
바이트가 그 실행의 보호값이다. GREET 입력으로 72바이트의 채움 값, 방금
받은 8바이트 보호값, 임의의 8바이트(저장된 이전 스택 포인터 자리), 그리고
`grant_access`의 실제 주소(리틀 엔디안 8바이트)를 이어 붙여 보내면 보호값
검사를 통과하고 `관리자 전용: pwnden{...}` 줄로 현재 실행의 flag가 온다.
`solve/solve.py`가 같은 순서로 접속해 이 값을 표준 출력에 그대로 출력한다.

## 드러난 보안 원리

컴파일러가 넣는 보호값은 "덮어쓰기가 있었는가"만 확인하므로, 공격자가 그
정확한 값을 먼저 알아내 그대로 되돌려주면 검사를 통과한다. 이 문제에서는
화면에 적힌 입력 범위를 실제 코드가 지키지 않는 별도의 결함(ECHO의
초과 읽기)이 그 값을 새어나가게 했다. 보호값을 통과한 뒤에는 저장된 복귀
위치를 덮어써 프로그램 안에 이미 있는 함수로 실행을 돌릴 수 있다. 새 코드를
주입할 필요가 없었다.

수정한 서비스는 ECHO 요청을 받는 계층에서 길이를 화면에 적힌 값과 같은
64바이트로 실제로 제한한다. GREET 입력을 저장하는 코드 자체는 그대로
남아 있지만, 보호값을 미리 읽을 방법이 없으면 그 값을 맞혀 변조를 통과할
수 없다. `patched/test.py`가 평소 사용(10바이트 ECHO 뒤 이름 입력),
경계값(64바이트 ECHO), 이전에 통하던 120바이트 요청, 음수 요청을 모두
확인한다.
