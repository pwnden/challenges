## 조사 결과

시험 게임의 서버는 달리기를 마친 뒤 플레이어가 보낸 기록 코드의 시간을 그대로 순위표에 올렸다.
화면은 별을 2초에 하나씩만 줍게 막았지만 그 제한은 서버가 등록할 때 다시 확인하지 않았다.
기록 코드의 시간을 한계보다 작은 값으로 바꾸자 서버가 받아 주었고 전설 트로피 코드가 나왔다.

## 조사 과정

1. 별 달리기를 열면 트랙 규칙에 별 6개, 별 사이 20m, 최고 속도 초속 10m가 적혀 있다.
   별 사이는 20m ÷ 초속 10m = 2초이므로 6개를 모두 줍는 데 최소 12초가 걸린다. 한계 기록은 12초다.
2. `달리기 시작`을 누르고 `별 줍기`를 6번 누른다. 버튼은 2초마다 한 번씩만 눌린다.
   순위표의 가장 빠른 기록은 12.64초다.
3. 모든 별을 주우면 기록 코드가 나타난다. 별마다 번호 `id`와 서버가 받은 시각 `t_ms`가 있고,
   마지막 별의 `t_ms`가 기록이 된다.
4. 기록 등록을 누르기 전에 기록 코드의 `t_ms`를 `1000, 2000, … 6000`처럼 더 작은 값으로 바꾼다.
   값은 앞의 별보다 커야 한다. 그다음 `기록 등록`을 누른다.
5. 서버가 6.00초 기록을 등록하고 순위표 맨 위에 올린다. 트로피 영역에 전설 트로피 코드가 나온다.

## 의뢰 완료 확인

트로피 코드 `pwnden{...}` 전체를 제출한다. 등록 성공 메시지만으로는 완료가 아니다.
코드는 실행 환경마다 새로 생성되므로 현재 시험 게임에서 나온 값을 제출한다.
달리기만 하고 기록을 바꾸지 않으면 기록은 12초보다 느리고 트로피는 나오지 않는다.

## 드러난 보안 원리

서버가 직접 측정한 값은 별을 받은 시각 하나뿐이다. 최종 기록 등록은 플레이어가 보낸 숫자를 믿었다.
화면의 2초 제한은 정상 사용자를 위한 안내였고, 요청은 같은 형식으로 다시 만들 수 있다.
별 사이의 거리와 최고 속도라는 규칙은 서버가 아는 값이므로 서버가 직접 확인해야 한다.

### 고친 동작

수정한 서버는 보고된 시간을 서버가 별을 받은 시각과 대조한다. 별마다 1초보다 크게 어긋나면
등록을 거부한다. 등록하는 기록은 서버가 측정한 마지막 별의 시각이다. 정상적으로 달린 기록은
그대로 등록되고, 한 번 등록한 달리기는 다시 등록할 수 없다.
별을 주우려면 앞의 별 이후 2초가 지나야 한다는 간격 검사는 처음부터 서버에 있었다.
기록을 만들 수 있는 시간의 하한을 서버가 다시 계산해 확인하므로 한계보다 빠른 기록은 만들어지지 않는다.
