## 시나리오 설정

- 표시 제목: 물리 한계를 넘은 달리기 기록
- 한 줄 소개: 별 달리기 운영자 깡총별이 한계보다 빠른 기록이 순위표에 올라왔다는 제보를 받고, 같은 규칙의 시험 게임에서 그런 기록이 실제로 등록되는지 확인해 달라고 의뢰한다.
- 공개 닉네임과 말투: 깡총별. 해요체로 짧게 말한다. “확인하지 못했습니다”처럼 아직 모르는 것을 구분해서 말한다.
- 의뢰인과 플레이어의 역할: 의뢰인은 작은 웹 게임의 운영자다. 플레이어는 시험 게임에서 별을 주우며 기록을 등록하고 순위표를 확인한다.
- 대상과 사건의 계기: 별 달리기의 기록 등록과 순위표다. 한계 기록보다 빠른 기록이 올라왔다는 제보가 계기이며, 제보는 시나리오 설정이고 실제 사고의 주장이 아니다.
- 길드를 찾은 이유: 직접 해결이 막힌 이유와 길드와의 접점은 따로 정하지 않았다. 브리핑은 깡총별이 시험 게임을 준비해 확인을 맡기는 데까지만 쓴다.
- 이번에 공개할 정보: 트랙 규칙(별 6개, 별 사이 20m, 최고 속도 초속 10m, 별 사이 2초), 기록 코드와 기록 등록의 존재, 한계 기록보다 빠르면 전설 트로피 코드가 지급된다는 것.
- 의뢰 목표와 완료 증거: 한계보다 빠른 기록을 등록할 수 있는지 확인하고, 지급되는 전설 트로피 코드 `pwnden{...}` 전체를 제출한다.
- 처음 전달할 사실: 한 번의 달리기에는 물리적인 최소 시간이 있고, 기록은 서버에서 확인한다고 운영자가 생각한다는 것. 이는 운영 원칙이며 현재 구현이 지킨다는 뜻이 아니다.
- 사건의 흐름: 순위표에 한계보다 빠른 기록이 올라왔다는 제보 → 운영자가 서버가 기록을 확인하는지 확신하지 못한다 → 시험 게임을 준비해 확인을 맡긴다. 구현은 `vulnerable/app.py`의 `Track`과 `vulnerable/policy.py`에서 이 흐름과 일치한다.
- 조사 중 발견할 사실: 별 사이 간격 검사는 서버에 있다. 기록 코드의 시간은 서버가 별을 받은 시각이지만, 기록 등록은 보내온 시간을 서버의 값과 대조하지 않고 그대로 순위표에 올린다.
- 풀이자에게 남긴 판단: 화면이 만든 기록 코드를 바꿔 볼지, 어떤 값으로 바꿀지, 한계가 얼마인지 계산할지를 풀이자가 정한다. 본문은 기록 코드가 바뀐다고 알려 주지 않는다.
- 학습 목표와의 연결: 화면에서의 제한과 서버의 검증은 다르며, 보고된 값을 서버가 측정한 값과 규칙에 대조해야 한다는 것을 직접 확인한다.

## 학습 목표와 대상

- 현재 계약의 category: web
- 학습 분야: web-security
- 세부 주제: web-business-logic. 서버가 앱의 규칙을 입력과 단계에 걸쳐 지켜야 한다는 원리의 한 사례로, 금액을 다룬 `refund-loop`와 다른 규칙(시간의 하한)을 다룬다.
- category 선택 근거: 브라우저와 HTTP 서비스로 풀므로 web이다.
- 보안 학습 목표: 화면이 만든 기록 코드를 바꿔 서버가 받아 주는지 관찰하고, 서버가 보고된 값을 직접 측정한 값과 규칙에 대조해야 하는 이유를 설명한다.
- 확인할 보안 원리: 화면의 제한은 서버의 검증이 아니다. 서버가 아는 값(시작 시각, 별을 받은 시각, 트랙 규칙)으로 클라이언트가 보고한 값을 검증해야 한다.
- 대상 풀이자: 주소와 웹 폼, 요청에 담기는 값을 읽을 수 있는 보안 입문자. 개발자 도구, CLI, Python 능력은 요구하지 않는다.
- 시작 조건과 성공 증거: 시험 게임이 준비된 상태에서 시작한다. 전설 트로피 코드가 서버의 응답으로 표시되면 성공이다.

## 의도된 풀이

| 단계 | 풀이자가 수행할 행동 | 발견·관찰할 내용 | 필요한 지식·도구 |
| --- | --- | --- | --- |
| 1 | 트랙 규칙과 순위표를 읽는다. | 별 6개, 별 사이 20m, 초속 10m이므로 한계는 12초이고 가장 빠른 기록은 12.64초다. | 웹 화면 |
| 2 | 한 번 달려 본다. | 별은 2초마다 하나씩 주워지고 기록 코드에 별마다 번호와 시간이 담긴다. | 웹 화면 |
| 3 | 기록 등록 전에 기록 코드의 시간을 한계보다 작은 값으로 바꾼다. | 값은 앞의 별보다 커야 한다. | `http-messages` |
| 4 | 기록 등록을 누른다. | 서버가 6.00초를 등록하고 전설 트로피 코드를 보여 준다. | 웹 화면 |

보안 학습 목표와의 연결: 3단계가 서버가 보고된 시간을 대조하지 않는다는 점을, 4단계가 그 결과 규칙에 어긋난 기록이 등록된다는 점을 보여 준다.

풀이자의 언어 지식: 화면의 버튼과 텍스트 상자만으로 풀 수 있다. 코드 이해나 작성은 필요하지 않다.

## 개념 관계

- 문제의 선수 개념: `web-addresses`, `http-messages`.
- 문제의 학습 개념: `client-reported-values`.
- 개념 간 선수 관계: `client-reported-values`는 `http-messages`를 요구한다. 순환이 없음은 검증 도구가 확인한다.
- 관련 읽기: `order-accounting`. 같은 기능의 결과를 기록과 규칙에 대조하는 점이 비슷하다.
- 공개 위치: 선수 개념은 시작 전, 학습 개념은 풀이 후 확인한다. 개념 문서는 퀴즈 앱 예제를 쓰며 이 문제의 트랙·기록 값을 쓰지 않는다.

## 난도 근거

- 선언한 값: 2 (1 입문, 2 초급, 3 중급, 4 고급, 5 심화)
- 선수 지식 부담: 웹 화면과 요청에 담긴 값 읽기. 최소 시간 계산은 나눗셈 한 번이다.
- 발견 난도: 기록 코드가 바꿀 수 있는 텍스트라는 점, 한계가 얼마인지, 값이 어떤 조건을 만족해야 하는지를 풀이자가 스스로 찾아야 한다. 한 번 달려 보는 데 12초 이상이 걸린다.
- 구현 부담: 코드·계산·도구 사용이 없다. 화면에서 숫자를 바꾼다.
- 풀이 의존성: 달려 보아야 기록 코드의 형식을 알 수 있고, 등록 전에 바꿔야 한다. 순서가 정해져 있다.
- 등급 판정: 한 기능의 금액 비교인 `refund-loop`와 비슷한 부담으로 2에 둔다. 작성자 판단이며 학습자 관찰로 확정하지 않았다.

## 다른 풀이와 정답 노출

- 확인한 다른 풀이: 서버가 별을 받은 시각을 직접 조작하는 길은 없다. 별 사이 간격은 서버가 막고, `solve.py`와 `patched/test.py`가 너무 이른 요청의 거부(429)를 확인한다. 요청을 직접 만들어 보내는 방식은 화면에서 바꾸는 방식과 같은 관찰을 얻는다고 판단했지만 실행으로 확인하지 않았다.
- 의도치 않은 지름길 점검: 달리기를 하지 않고 기록을 등록할 수는 없다. 모든 별을 줍기 전의 등록은 거부(409)되고, `patched/test.py`가 확인한다. 트로피 코드는 순위표 응답에 한계보다 빠른 기록이 있을 때만 포함되고 서버 렌더링 상태에 코드가 없음을 웹 테스트가 확인한다.
- 본문 노출 점검: 본문은 한계 기록이 12초라는 값과 기록 코드를 바꾸라는 말을 하지 않는다. 힌트 1이 기록 코드가 화면이 만든 텍스트라는 점을, 힌트 3이 값을 바꾸는 방법을 말한다.
- 필요한 힌트: 3개. 1번은 화면의 제한과 서버의 확인 구분, 2번은 기록 코드의 시간 값 읽기, 3번은 값을 바꿔 등록하는 구체적인 방법을 다룬다.
- 해설: 한계 계산, 달리기, 기록 코드 수정, 트로피 확인, 수정 서버의 대조를 설명한다. 간격 검사가 처음부터 서버에 있었다는 점도 적었다.

## 검증과 리뷰

- 실행 범위: 실제 대상. 서비스 하나를 Docker로 실행하고 수정 서버는 `compose.patched.yaml`로 `policy.py`만 바꾼다.
- 기술 검증: 2026-10-13, 카탈로그 형식 검사 23개, 작성자 실행기 `verify.py lap-record`(풀이·수정 서버 대조·정리), Vue 타입 검사와 렌더링 테스트 15개를 통과했다. 같은 날 브라우저에서 달리기·기록 코드 수정·등록·트로피 표시와 모바일 폭의 줄바꿈을 확인했다. 브라우저 확인 중 기록 코드 텍스트 상자의 내용 교체는 자동 조작 도구가 전체 선택을 하지 못해 스크립트로 값을 넣고 입력 이벤트를 보냈다.
- 학습 리뷰: 독립 리뷰어의 풀이 관찰은 아직 없다. `quality/reviews/lap-record.json`의 일곱 항목이 모두 미평가이다.
- 리뷰 관찰: 문장 검토는 `quality/text-reviews/lap-record/`에 기록한다.
- 맥락 확인: 문장 검토가 첫 의뢰 메시지만으로 의뢰인과 대상의 관계, 증상, 확인할 일을 식별하는지 확인한다. 실제 처음 읽는 사람의 정리는 아직 받지 않았다.
- 용어 확인: 브리핑, 화면, 힌트, 해설이 기록 코드·별·한계 기록·전설 트로피를 같은 이름으로 부르는지 대조한다.
- 배포 준비 상태: 독립 학습 리뷰가 남아 있어 배포 준비 완료로 표시하지 않는다.
