풀이자는 자료를 읽고 사용할 도구와 비교 기준을 선택한다. 선택형 힌트가 막힌
판단을 돕고, 해설이 재현 명령과 결론을 설명한다. 공통 개념은 학습 연결에서
필요할 때 읽는다. 명령 예제를 기본 본문에 제공했던 기존 설계의 시작 정보·판단·
힌트 평가는 재검토 대기이며, 새 본문에 대한 심사를 완료했다고 간주하지 않는다.

이하 검토·설계 기록은 작성 당시 버전의 근거다. 본문의 명령 예제나 조작 설명을
언급하는 과거 기록은 현재 기본 브리핑의 제공 정보로 사용하지 않는다.

## 설정과 목표

노을책갈피는 문서 서비스의 운영 담당자다. 새 내보내기 기능이 기존 조회의
소유권 경계를 지키는지 재검증하려고 guest 계정을 길드에 제공한다.

- 분야: `web-security`, 주제: `web-access-control`, category: `web`.
- teaches: 같은 자원의 다른 작업에도 서버에서 소유권을 확인해야 함을 입증한다.
- requires `terminal-commands`, `http-messages`, `http-cookies`, `curl-json`: 로그인·
  쿠키 저장·GET/POST·JSON 필드·상태 비교 범위를 본문에 제공한다.
- 대상: 준비된 CLI 요청을 바꿀 수 있는 초급자. 난도 2 초급을 제안한다.
  자기 문서와 다른 소유자, 일반 조회와 내보내기를 연결하는 비교가 필요하다.
- Python 작성은 일반 풀이의 선수 능력이 아니다. 기존 note-vault의 소유권 개념을
  다른 API 작업으로 옮기는 진행 문제다.

## 대상과 의도된 관찰

실제 HTTP API에서 guest 로그인은 서버가 관리하는 무작위 쿠키를 발급한다.
두 문서는 서버가 보관하며 문서 42의 본문에 실행마다 주입한 flag가 있다.
목록은 ID·소유자·제목만 반환하고 일반 조회는 소유권을 검사한다.
summary는 목록과 같은 공개 필드만 제공한다. full 내보내기에서 취약한 정책이
소유권 검사를 생략한다. GET /의 실제 안내에서 두 형식을 확인할 수 있다.

1. 로그인하지 않은 요청은 거부된다.
2. 자기 문서의 조회·내보내기는 둘 다 정상이다.
3. 타인 문서 조회는 거부된다. summary의 200에는 본문이 없지만 full은 본문을 반환한다.
4. 수정 후에는 타인 full이 거부되고 정상 summary와 자기 full은 유지된다.

자동 해답은 curl·jq만 사용하고 수정 서버의 403에서 계약상 거부 코드 3을 반환한다.
`patched/test.sh`는 정상 기능·타인 소유권·본문의 소유자 조작·잘못된 JSON과 ID·
로그인 없는 요청·위조 쿠키를 실제 HTTP로 검사한다. 같은 CLI 요청을 직접 비교하는
대안 경로도 자동 해답과 동일한 관찰을 얻는다.
200 상태의 본문 없는 정상 요약을 오탐으로 구분하는 판단을 추가한다. 잘못된
형식·배열 형식 입력을 거부하고 full만 취약/수정 차이를 보이는지 검사한다.

서비스 이미지는 고정 Python base와 stdlib만 사용하며 도구 이미지와 분리한다.
HTTP 컨테이너 하나를 격리 네트워크에서 실행한다. 플레이어 도구는 terminal이다.
작성 자료와 해답은 로컬 카탈로그에서 비밀로 취급하지 않는다.
