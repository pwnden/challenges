# 회원 검색 데스크 화면 문구 갱신 검토

2026-10-14, Claude 작성자 검토. 범위: 검색 폼·검색 조건·검색 결과 영역으로 다시 구성하며 바뀐 문구.
`vulnerable/web/App.vue`와 `vulnerable/app.py`를 대조했다. 실제 학습자 관찰은 포함하지 않는다.

| 문구 | 기준 | 대응 근거 | 판정 |
| --- | --- | --- | --- |
| "공개 회원 mira와 sol의 소개를 검색할 수 있습니다." | T1, T5 | 대상 서버가 실제로 공개(public=1)로 두는 회원 두 명의 닉네임과 일치한다. 검색 자체는 전체 레코드를 대상으로 하므로 "검색할 수 있다"는 안내된 대상만 한정하지, 실제 질의 범위를 과장하지 않는다. | 충족 |
| "이번 검색에 사용한 조건" 제목과 그 아래 코드 블록 | T4, T5 | 서버가 생성한 실제 SQL 조건문(`data.query`)을 그대로 보여주는 영역이며, 조건이 비공개 레코드까지 포함하는지는 플레이어가 직접 판단할 몫으로 남긴다. | 충족 |
| "검색 결과가 없습니다." (빈 결과 안내) | T3 | `data.matches`가 빈 배열일 때만 보이며, 서버가 숨긴 레코드의 존재를 암시하지 않는다. | 충족 |
| "public = 1은 공개 회원, public = 0은 비공개 회원을 뜻합니다." | T4, T5 | `vulnerable/app.py`가 실제로 쓰는 컬럼명·값과 일치하는 용어 설명이며, 이 값을 어떻게 조회에 이용할지는 말하지 않는다. | 충족 |

기본 본문과 화면은 검색 대상·조건 표시·결과 표를 제공한다. 조건문에 비공개
레코드가 포함되게 만드는 구체적인 입력은 본문·화면 어디에도 없고 힌트·해설에서만
다룬다. 좁은 화면에서의 표 가로 스크롤은 의도된 동작이다.
