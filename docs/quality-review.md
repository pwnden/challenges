# 문제별 품질 평가

문제의 학습 설계와 검증 근거는 작성자용 `quality/reviews/<slug>.json`에서 관리한다.
평가 항목과 비중은 `quality/rubric.json`에 있다. 플레이어 계약과 화면에는 점수를
추가하지 않는다. 정답을 포함할 수 있는 내부 평가 자료다.

## 평가 방법

브리핑과 자료를 먼저 읽고, 힌트·해설을 닫은 상태에서 가능한 시작 행동과 판단을
정리한다. 그다음 힌트·해설·실제 대상·대조 검사를 대조한다. 자동 해답 성공은
실행 재현의 근거로 쓰며, 초심자의 이해나 화면 전체 풀이의 증거는 별도로 수집한다.

| 항목 | 비중 | 확인할 근거 |
| --- | ---: | --- |
| 학습 목표 | 10 | 의뢰, 관찰 가능한 보안 원리, 완료 증거의 일치 |
| 시작 정보 | 10 | 조사 범위, 자료, 도구 조작, 선수 능력의 설명 |
| 판단과 난도 | 15 | 선택·비교·추론 단계와 그럴듯한 오답의 구분 |
| 증거와 대조군 | 15 | 정상·거부·오답·변조·누락 검사, 패치와 정상 기능 |
| 힌트 | 10 | 기본 본문과 정답의 분리, 막히는 판단에 대한 도움 |
| 해설 | 10 | 행동·관찰·결론·원인·보호 방법과 결론의 한계 |
| 실행 재현 | 10 | 실제 이미지의 해답·선언한 패치·정리 실행 기록 |
| 브라우저 풀이 | 10 | 검색부터 준비·풀이·정답/오답 제출·종료까지 화면 조작 |
| 독립 학습자 | 10 | 대상 수준 풀이자의 시간·막힌 단계·힌트·원리 이해 |

각 항목은 다음 0–4 수준으로 판정한다. 이유, 실제 파일 경로와 그 파일에 있는
정확한 발췌, 보완 행동을 함께 쓴다. 근거의 의미를 읽고 판단하는 일은 검토자의
책임이며 검사기는 인용문 존재만으로 점수를 결정하지 않는다.

- `0`: 확인한 결과 기준을 충족하지 못한다.
- `1`: 목표나 의도는 있으나 실제 구현·설명이 크게 부족하다.
- `2`: 일부 충족하며 구체적인 누락이나 불일치가 있다.
- `3`: 해당 난도에 필요한 기본 기준을 충족하는 근거가 있다.
- `4`: 기본 기준과 함께 혼동하기 쉬운 사례·대안·경계까지 구체적으로 다룬다.
- `null`: 아직 평가하지 않았거나 필요한 검증 기록이 없다. 다음 검증 행동을 적는다.

**충족 점수 = Σ(항목 비중 × 수준 / 4)**다. 미검증 항목은 입증된 점수에 기여하지
않으며, 따로 평가 비중과 미검증 목록을 표시한다. 예를 들어 70/100·평가 비중
80%는 20%를 아직 평가하지 않았다는 뜻이다. 성공 확률이나 학습자 만족도 70%를
뜻하지 않는다. 통과선이나 공개 승인은 점수만으로 자동 결정하지 않는다.

입문 문제는 한 원리를 직접 관찰하는 것으로 판단 기준을 충족할 수 있다. 초급은
2–3개 단서 연결이나 오답 구분을 확인한다. 명령 수·자료 크기·도구 수로 난도를
높게 평가하지 않는다. 힌트가 0개인 경우에도 본문만으로 입문 목표를 수행할 수
있으면 타당하다. 작성자 자료에는 근거가 있는데 플레이어 본문에 없으면 시작
정보 점수를 내리고 해당 위치를 보완한다.

실행 항목은 날짜가 있는 작성 기록이나 실제 실행 결과를 인용한다. 과거 기록의
인용은 이번 검토에서 새로 실행했다는 뜻이 아니다. 브라우저·학습자 항목은 각각
실제 세션 기록이 필요하다. 화면 검사는 PTY 검증으로, 독립 리뷰는 작성자의
자동 해답으로 대체하지 않는다. 증거 종류도 항목마다 검사한다.

## 검사와 갱신

```sh
python3 -B tools/quality.py
python3 -B tools/quality.py --json
```

첫 명령은 문제별 점수·평가 비중·미검증 목록을 표시한다. JSON 출력에는 보완
행동도 포함된다. 문제마다 정확히 한 평가가 있어야 하며 다음 사항을 검사한다.

- 항목 누락, 잘못된 수준, 빈 판정 이유, 근거 없는 점수.
- 미검증·부분 충족 항목의 후속 행동 누락.
- 근거 파일이 저장소 밖에 있거나 인용문이 바뀐 경우.
- 평가 당시 소스와 현재 소스의 불일치.

`source_sha256`은 문제 디렉터리, 공통 지식, 계약, 평가 기준 및 인용 파일의
경로와 내용을 묶은 SHA-256이다. 소스가 바뀌면 기존 평가는 오래된 것으로
차단된다. 서비스 문제는 공통 웹 대상 소스도 포함한다. 빌드 산출물과 캐시는 제외한다.
검토자가 변경 내용을 읽고 수준·이유·근거·보완 사항을 재평가한 뒤
날짜와 해시를 갱신한다. 해시만 자동으로 바꾸는 명령은 제공하지 않는다.
새 문제에도 같은 평가 파일을 추가한다. 점수는 계산해서 출력하므로 총점을
수작업으로 수정하지 않는다.

CI와 `tools/publish.py`는 평가 누락·근거 불일치·오래된 평가를 검사한다. 학습자
리뷰가 없는 경우는 `null`로 드러내며, 기존 기술 검증을 수행하는 경로는 유지한다.
미검증 평가가 있다고 검토를 완료한 것으로 선언하지 않는다.

## 독립 심사단

저장소의 [문제 검토자 스킬](../.agents/skills/challenge-reviewer/SKILL.md)은 기본
3명의 가벼운 subagent로 시작하고, 큰 의견 차이·판정 충돌·점수를 뒷받침하지
못하는 근거가 있으면 대안 풀이·도구·환경 검토자 2명을 추가한다. 최대 5명이다.
사용자가 처음부터 5명을 요청할 수도 있다. 기존 점수와
다른 심사 결과를 숨기고 항목별 중앙값을 계산한다. 원본 점수·판정 이유·근거와
부모의 조정 기록은 `quality/panels/<slug>/<run-id>.json`에 보존한다.
기본 persona는 초급 학습자 관점·증거 검토자·교육 설계자다. 역할마다 관찰 질문을
다르게 주며, 채점 기준과 비중은 공통으로 유지한다. 역할과 발견 차이도 기록한다.
추가 심사자는 앞선 점수를 보지 않고 놓쳤을 수 있는 결함과 반례를 찾는다.
최초 투표와 합산을 보존해 5명 결과와 비교하고, 확대 이유와 새로 확인된 유효 결함을
감사 기록의 `escalation`에 남긴다. 점수 일치나 전원 미검증인 세션 항목만으로
확대하지 않는다. 여러 문제에서 추가 심사의 발견 효과를 보고 기본 인원을 판단한다.
2단계 이상 점수 차이, 검증 여부 불일치, 일부 심사자의 0점은 근거를 재검토한다.
미해결 항목은 점수에 기여하지 않는다. 같은 모델의 공통 편향과 실제 학습자
검증의 부재는 별도로 남는다. 스킬 생성 시험은 현재 문제 점수를 갱신하지 않는다.

## 최초 검토 범위

2026-10-03 Codex가 20개 문제의 본문·해설·작성 기록·대조 검사를 대조해 초기
평가를 작성했다. 실행 점수는 기존 날짜별 검증 기록을 인용한다. 브라우저 전체
풀이와 독립 학습자 검토는 모든 문제에서 미검증이다. 최초 점수는 작성자 검토이며
독립 평가로 취급하지 않는다. 문제별 발견과 다음 작업은 각 JSON에 남긴다.
