# 클라이언트가 보고한 값과 서버의 검증

앱이 서버에 보내는 값에는 두 종류가 있다. 서버가 직접 만들거나 측정한 값과,
사용자의 브라우저나 앱이 알려 주는 값이다. 화면의 버튼이 막혀 있거나 입력 칸이
숫자만 받는 것은 사용자에게 보여 주는 안내일 뿐, 서버가 그 값을 믿어도 되는 이유가 되지 않는다.
브라우저에서 보내는 요청은 사용자가 같은 형식으로 다시 만들 수 있기 때문이다.

예를 들어 퀴즈 앱이 풀이를 마칠 때 "정답 12개, 소요 시간 40초"를 서버에 보낸다고 하자.
화면은 문제를 하나 푸는 데 최소 3초가 걸리도록 만들었더라도, 서버가 보고된 숫자를
그대로 저장하면 사용자는 "정답 12개, 소요 시간 2초"를 보내 순위표를 바꿀 수 있다.

서버는 보고된 값을 규칙에 대조해 검증해야 한다. 서버가 직접 측정할 수 있는 값을
기준으로 삼는 것이 가장 확실하다. 이 예에서는 서버가 퀴즈를 시작시킨 시각과 제출을 받은
시각의 차이가 보고된 소요 시간보다 짧을 수 없다. 문제 수와 문제당 최소 시간처럼 앱이
정한 한계도 서버가 다시 계산해 확인한다.

값이 정해진 범위를 벗어나는지만 확인하면 부족하다. 값들 사이의 관계가 앱의 규칙과 맞는지,
보고된 시각이 서버가 아는 시각과 맞는지, 같은 기록을 두 번 등록할 수 없는지도 함께 본다.
화면에서의 제한은 정상 사용자를 돕는 장치이고, 서버의 검증은 규칙을 지키는 장치다.
